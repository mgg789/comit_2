# Comit — продуктовое видение (консолидация ТЗ ФСП + видение команды)

**Comit** — сервис подбора ИТ-персонала с обратной механикой: соискатели автоматически распределяются по категориям на объективно подтверждаемом профиле, работодатель сам находит категорию и выходит на конкретного кандидата с предложением и ЗП. Проект хакатона ЛЦТ 2026, спецтрек ФСП; амбиция — продукт, решающий проблемы hh.ru, зафиксированные в [[01-hh-research-apr-sep-2026|исследовании]].

## Проблемы рынка → решения Comit (маппинг на исследование)

| Проблема из исследования | Решение в Comit |
|---|---|
| Молчание после отклика | Жёсткие статусы у обеих сторон + SLA-механика (форма обратной связи обязана быть заполнена, иначе ограничение вакансии) |
| Низкая конверсия откликов | Обратная механика: кандидат не рассылает резюме — работодатель сам приходит с ЗП |
| Нерелевантные рекомендации | Категория по тесту + строгий фильтр + векторный матчинг + объяснимость выдачи |
| Непрозрачный отсев | Обоснование попадания в подборку, статусы каждого этапа |
| Скрытые условия | ЗП «от–до» обязательна в вакансии и приглашении; кандидат видит условия до общения |
| Недостоверный опыт | Рейтинг подтверждённых полей: очки только за верифицируемое (тесты, проекты, ФСП) |
| Неактуальные вакансии | Статусная модель + ограничение времени на обратную связь + актуальность профиля через регулярные задания |
| Перегрузка работодателя | «Комбайн»: строгий фильтр → скоринг → топ-k → реранкер; тиндер-интерфейс разбора |
| Тестовые на этапе собесов | Тестирование ДО рынка: грейд подтверждён до попадания в базу |

## Роли и поверхности (4 web-приложения)

1. **Приложение работодателя** — создать/менеджерить вакансии, статистика; когда вакансия набрала отранжированных кандидатов — «тиндер»-разбор; с оставшимися — пост-отбор: назначить собес, тестовое задание, оффер/отклонить с причиной.
2. **Приложение соискателя** — управление своими данными, верификация данных, приглашения работодателей (сравнение предложений), агрегированные рекомендации «что доработать, чтобы брали».
3. **Сервис тестирования** — подтверждение знаний, техсобесы, микро-задачи (отдельный крупный сервис; подробнее в [[60-testing-engine]]).
4. **Общая витрина вакансий и welcome-морда** — в последнюю очередь.

## Жизненный цикл кандидата и вакансии (высокоуровнево)

1. **Соискатель**: заполняет данные → получает 0 очков рейтинга → подтверждает поля (опыт, проекты, навыки, грейд-тест) — каждое подтверждение добавляет очки → проходит опрос специализации + грейд-тест → попадает в категорию (специализация × грейд) → в общий пул с строгими параметрами и личным вектором.
2. **Вакансия**: создаётся с обязательными строгими параметрами (стек, специализация, грейд, ЗП от–до) → строится вектор по описанию и свободным параметрам → статус Active → запускается «комбайн» (см. [[50-matching-engine]]) → топ-k кандидатов проходят реранкер → статус Has candidates.
3. **Разбор (тиндер)**: работодателю показываются отобранные; rejected = visited (не возвращаются в пул этой вакансии никогда), attractive → пул одобренных; каждое решение корректирует вектор вакансии; система подсовывает контрольных кандидатов (exploration с маскированной коррекцией) — см. [[50-matching-engine]].
4. **Пост-отбор**: у кандидата появляется карточка работодателя; приняв её, кандидат в чате назначает собес (выбор времени в UI); результат — принят/не принят; не принято → обязательные формы обратной связи обеих сторон в течение 3 рабочих дней, иначе вакансия ограничивается системой на 4 дня. Принят → вакансия закрывается, статус сотрудника «Работает».
5. **Добор**: переотбор запускается по порогу изменчивости пула (новые кандидаты / изменение данных); без visited, pending, attractive; улучшение pending — остаётся; отклонённый возвращается через личный порог изменения.

## Ключевые продуктовые ставки (что должно «выстрелить» на жюри)

1. **Обратная механика + объяснимость** — работодатель видит не «чёрный ящик», а «почему этот человек»: совпавшие фичи, вклад рейтинга, подтверждения.
2. **Живая механика тестирования** — параметризованная генерация вариантов (анти-утечка) + калибровка сложности; не заглушка.
3. **Рейтинг подтверждённости** — единая валюта доверия профиля (очки), наглядная у работодателя.
4. **Тиндер-луп с обучением вектора вакансии** — оригинальная механика, отличающая от hh и LHH; демо-фишка «вакансия учится у работодателя».
5. **Обратная связь как контракт** — SLA на ответы, форма «почему не взяли», штраф-механика — прямое решение проблемы молчания.

## Целевая аудитория MVP

- Работодатели: ИТ-компании (демо — 2–3 синтетических профиля компаний).
- Соискатели: ИТ-специалисты, в т.ч. участники соревновательного движения ФСП (спортсмены без опыта работы — важная категория, конверсия спортивного опыта в карьерное преимущество).
- Демо-данные: синтетические (ТЗ разрешает только их) — см. [[70-mvp-scope]].
