# Идеи за рамками MVP (крутые, не обязательные)

> Из них 2–3 стоит упомянуть в презентации как «дорожную карту» (жюри любит продуктовую зрелость), часть можно превратить в концепцию для допкритериев (защита от фиктивных вакансий, ATS).

## Продуктовые

1. **«Разряд → грейд» конвертер.** ФСП выдаёт разряды по программированию (участники спецтрека тоже могут их получить). Продуктовая идея: официальная шкала соответствия «разряд III ≈ готов к junior-задачам» и т.п. — уникальная валюта доверия, которой нет ни у кого. Кандидат конвертирует спортивный опыт в карьерное преимущество буквально (это формулировка ТЗ).
2. **Gap-анализ «что докачать».** У соискателя уже в видении есть «агрегированные рекомендации». Усилить: система знает реальные требования открытых вакансий — показывает конкретные недостающие навыки до конкретных категорий вакансий («до middle+ бэкенда не хватает подтверждённого опыта с очередями: вот 3 задачи»), связывая с регулярными заданиями.
3. **Зарплатная прозрачность.** Публичная витрина распределений ЗП по категориям (агрегат по приглашениям и вакансиям) — прямой ответ на «скрытые условия» из исследования и естественный welcome-контент.
4. **Задача недели от компаний.** Регулярные короткие задания как контент: компании публикуют открытые мини-челленджи, лучшие решения видны работодателям — брендинг для работодателя, витрина для кандидата.
5. **Лидерборды категорий.** Сезонные рейтинги внутри категории (спортивная механика ФСП перенесена в найм): топ подтверждённых профилей, свежие достижения поднимают позицию. Живость базы + геймификация.
6. **Пост-найм петля.** Через 1–3 месяца после найма — опрос обеих сторон («сработались?»), метрика качества матчинга замыкается на алгоритм: настоящая рекомендательная система с ground truth. Для хакатона — концепция + мок.

## Доверие и безопасность (весит для гос-трека)

7. **Карма работодателя.** Публичные SLA-статистики: скорость ответов, доля обратной связи, завершённость вакансий. Фиктивные вакансии вырождаются сами — прозрачность вместо модерации. (Концепция «защиты от фиктивных вакансий» по ТЗ.)
8. **Анти-AI-читинг в тестах.** Задачи, где важно рассуждение в реальном времени: «подход-режим» (текстовое рассуждение с временной осью), транскрипт-анализ, задачи с уникальными twist-параметрами, которые LLM не решат без понимания конкретного варианта. Честно и актуально (проблема работодателей из исследования).
9. **Верификация компании.** УКЭП/Госуслуги-совместимый путь верификации юрлица в концепции защиты от фиктивных вакансий.

## Технические

10. **ATS-коннектор.** Webhook-API исходящих событий (приглашение принято, оффер) + экспорт в форматы популярных ATS; входящий REST для синхронизации статусов. (Концепция ATS-интеграции по ТЗ.)
11. **Живой профиль (freshness).** Видимый кандидату индикатор актуальности: подтверждения «стареют» (decay), регулярные задачи обновляют свежесть — работодателю видно, что профиль живой. Уже частично в скоринге (w_a·freshness) — оформить в UI.
12. **Мульти-категорийность.** Кандидат в нескольких категориях (бэкенд + ML) с раздельными тестами — увеличение поверхности матчинга без раздувания профиля.

## Для презентации: что из этого назвать

- В MVP демо: тиндер-луп с обучением вектора + SLA/обратная связь (наше отличие).
- В дорожной карте: разряд→грейд, gap-анализ, карма работодателя, пост-найм петля.
- В концепции (документ): ATS, защита от фиктивных вакансий, верификация компаний.
