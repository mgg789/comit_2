# Оформление PDF-резюме

PDF работодателя и PDF владельца формирует `services/matching-engine/src/matching_engine/resume.py` через ReportLab. Обе версии используют одну верстку: белый A4, крупный заголовок, тёмная типографика, тонкие голубые разделители, строки навыков на голубом фоне, повторяющийся колонтитул и номер страницы. Палитра соответствует актуальному интерфейсу работодателя: `#272930`, `#bfe2ff`, нейтральный серый. Текст остаётся выделяемым.

В верхнем поле каждой страницы размещается тёмная капсула из хэдера: реальный SVG-знак `dec04dda54551634f35985932f0a53e8bcda20f5.svg` и надпись `comit` шрифтом Moon Walk из `packages/ui-kit/src/design-assets/fonts/moon-walk.ttf`. Пропорции исходной `.brand` сохранены: высота 66, боковые поля 32, знак 38, промежуток 12, шрифт 32. Капсула заранее растрирована в прозрачный PNG с четырёхкратным разрешением и входит в package-data (`fonts/*.png`). Конвертер SVG и шрифт Moon Walk не нужны в рабочем сервисе. PNG воспроизводит фирменный знак, а основной текст PDF остаётся векторным.

## Шрифты и автономность

В PDF встраиваются Inter Regular и Inter Bold с поддержкой кириллицы. Пакетные TTF получены из существующих `packages/ui-kit/src/design-assets/fonts/Inter-{Regular,Bold}.woff2` сменой контейнера через fontTools (`TTFont`, `flavor=None`, `save`); контуры не изменялись. Это статические шрифты, дополнительная библиотека для конвертации в рабочем сервисе не нужна. Файлы и SIL OFL 1.1 входят в package-data (`fonts/*.ttf`, `fonts/LICENSE.txt`). Лицензия: [Inter](https://github.com/rsms/inter/blob/master/LICENSE.txt).

## Содержимое и приватность

Названия навыков и именованные уровни (`Intern` - `Senior+`) берутся из генерируемого снимка единого `packages/shared/src/skill-catalog.ts`. Команда обновления из корня: `python services/matching-engine/scripts/generate_resume_catalog.py`; проверка актуальности: та же команда с `--check`. Снимок `artifacts/resume-skill-catalog.json` включён в пакет сервиса. Неизвестные исторические ключи остаются как есть; уровень 0 сохраняет UI-подпись «Уровень не выбран». Регрессионный тест проверяет совпадение снимка с каноническим каталогом; ручное редактирование снимка не требуется.

Оформление сохраняет действующую публичную проекцию: имя, email, телефон и контактные ссылки в свободном тексте скрываются. PDF владельца содержит его контакты. Статусы грейда, навыков и подтверждений берутся из типизированного профиля; дизайн не добавляет навыков, рейтингов или выводов о кандидате. Пользовательский текст экранируется перед передачей в Paragraph, поэтому HTML не становится разметкой PDF.

О себе, проекты, опыт, достижения, предпочтения и внешние подтверждения выводятся при наличии данных. Длинные абзацы и слова переносятся на следующие страницы без сокращений. Заголовки разделов и записей сохраняют связь со следующим элементом; основной текст может разделяться между страницами. Короткий профиль может занимать одну страницу, большой - несколько.

## Проверка

Из `services/matching-engine`: `PYTHONPATH=src python -m pytest tests/test_resume.py tests/test_rerank_resume.py -q`. Проверяются публичная/личная проекции, буквальный HTML, кириллица, статусы, встраивание обоих Inter, цветовой акцент, наличие разделов и сохранность конца максимального длинного профиля. Для визуальной проверки: `pdftoppm -png <resume.pdf> <output-prefix>` и просмотр всех страниц. Синтетические образцы не являются данными кандидатов.

## Обновление уже опубликованных PDF

Версия оформления записывается в стандартные PDF Keywords (`comit-resume-template:2026-10-v3`). `Store.resume` отдаёт сохранённые bytes, когда обе проекции имеют актуальную версию. При первом запросе старого шаблона метод берёт существующий `PIPELINE_LOCK`, повторно читает опубликованный профиль и одним UPDATE сохраняет новые публичный и личный PDF. Следующие запросы не запускают рендер повторно. Обновление происходит только для текущих `candidate_id/revision`, состояния `ready` и активного `schema_version`; UPDATE дополнительно проверяет сохранённый `schema_hash`. Если профиль отозван, заменён или сменилось поколение схемы во время ожидания блокировки, запрос получает прежний `NotFoundError`.

Обновляются исключительно `public_pdf` и `owner_pdf`. Ревизии профиля, категория, векторы, публичная проекция, `published_at` и события остаются прежними; новое согласие или повторная категоризация не требуются. ACL маршрутов сохраняются: выбор личного PDF остаётся решением защищённого API. Для первого запроса старого шаблона рендер выполняется внутри короткой транзакции с блокировкой публикации; повторные запросы используют кеш.

PostgreSQL-регрессии: `PIPELINE_TEST_DATABASE_URL=<isolated-test-dsn> PYTHONPATH=src python -m pytest tests/test_pipeline_integration.py -k 'resume or consent_withdrawal' -q`. Использовать только отдельную тестовую базу: fixture очищает pipeline-таблицы. Проверяются обе проекции/контакты, неизменность остальных полей публикации, единственное обновление при параллельных GET и повторная проверка всех fences после ожидания блокировки.
