# Кабинет кандидата

Приложение `apps/candidate` переносит макет Figma `444:15763` и использует общий дизайн работодателя: кнопки, стекло, формы, Select, состояние загрузки, раскрытие страниц, фон входа и EmailLogin из `@comit/ui-kit`. Общие ресурсы собираются из пакета; оригинальные ресурсы экранов кандидата находятся в `apps/candidate/public/design`. Базовые компоненты описаны в [ui-kit.md](ui-kit.md).

## Экраны и данные

- `/resume`: собственное резюме из `GET /api/candidate/profile`. Отсутствующий профиль — состояние создания. Вход в редактор не создаёт запись на сервере. `PATCH /api/candidate/profile` сохраняет реальные поля с `expected_revision`; создание использует ревизию `0`. После конфликта пользователь явно загружает актуальное резюме перед новым редактированием. Поля `fsp_id` и `fsp_claim_id` доступны только для чтения: они меняются через отдельный серверный контур проверки и исключены из обычной записи резюме. Доказательства и отметки подтверждения никогда не отправляются как редактируемые поля.
- `/offers`: все страницы `GET /api/candidate/recruitment`, фильтрация по состоянию и поиск по компании/названию. Каждая карточка показывает неизменяемую зарплатную вилку из приглашения и состояние процесса. Вместо выдуманного логотипа используется инициал компании.
- `/offer/:id`: `GET /api/candidate/recruitment/:id`. Просмотр фиксируется действием `view`, только если сервер разрешает его, один раз при открытии процесса. Кнопки принятия/отказа, принятия оффера и отказа от времени собеседования основаны на `allowed_actions`. Каждая запись в `POST /api/candidate/recruitment/:id/actions` содержит текущую ревизию и стабильный UUID повторной попытки. Неизвестный исход сетевого запроса не создаёт новый ключ для одинакового действия. После смены страницы поздний ответ не подменяет открытое приглашение.
- `/statistics`: считает приглашения за последние 30 дней, принятые и ожидающие ответа по всем доступным страницам. Отображает указанные кандидатом навыки, а не подтверждённый грейд или выдуманные оценки.

## Переписка

Переписка использует тот же `RecruitmentConversation` из `@comit/ui-kit`, что и кабинет работодателя: сообщения, плавное появление, стеклянный composer, вложения и скачивание. Авторизация не переносится вместе с UI: транспорт кандидата всегда вызывает только candidate-методы API. История читается курсором при `chat_available`; отправка и файлы разрешены только при `chat_writable`. После неизвестного исхода отправки сохраняются неизменный текст, вложения и UUID для повторной попытки; редактирование до разрешения этой попытки блокируется. Вложения ограничены восемью файлами по 8 МБ и скачиваются через авторизованный endpoint.

## Согласие и границы

Согласие на обработку резюме и показ в подборе отделено от согласия регистрации. Новые значения не включаются автоматически. API снятия обработки или видимости также отзывает обучение, если оно ранее было разрешено; редактор требует обе отметки для обычного сохранения; отдельная кнопка отзыва требует подтверждения в общей модалке. Редактор не включает обучение самостоятельно. Неизменённое согласие не пересохраняется при правке обычных полей.

Исходный профиль не содержит фотографии: вместо чужого лица из макета показываются инициалы. Указанный кандидатом грейд явно отмечен как его оценка. Для следующих блоков нет интегрированных данных этого кабинета: показы профиля, рейтинг, место среди стеков, рынок зарплат, история и запуск грейд-тестов, еженедельное задание. Их панели сохраняют структуру макета, показывают недоступность и не выдают образцы за реальные значения. Отдельный вход в проверку ФСП из этого кабинета пока не реализован.

## Проверка

- `pnpm --filter @comit/web-candidate typecheck`
- `pnpm --filter @comit/web-candidate build`
- `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs CANDIDATE_URL=http://127.0.0.1:5177/candidate/ node tests/candidate-browser.mjs`
- `CANDIDATE_REDUCED_MOTION=system` для той же проверки системного уменьшения движения.
- `tests/candidate-auth-browser.mjs` проверяет общий вход с ролью кандидата.
- `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs CANDIDATE_URL=http://127.0.0.1:5177/candidate/ node tests/candidate-runtime-browser.mjs` проверяет пагинацию приглашений.

Браузерные сценарии перехватывают API и используют только синтетические данные: реальные письма, сессии, приглашения и сообщения не создаются. Они проверяют CAS, исключение серверных полей ФСП из записи профиля, блокировку сохранения без согласий, пагинацию, зарплату, просмотр приглашения, повтор с прежним ключом, отказ от времени собеседования, переписку и ширины 1920/1024/390.

## Статистика и готовность подбора

Статистика использует единую сетку с общими строками двух колонок. Плашка места среди всех стеков удалена; навыки показываются диаграммой индивидуальных уровней без видимых подписей, с доступными названиями для скринридера. Корневой контейнер удерживает нижние отступы внутри фона. Проверка: `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs node tests/candidate-statistics-browser.mjs`.

В резюме каждый домен, стек и личный навык показывает собственный уровень 0–7 и отдельно серверный статус проверки. Общая категория опыта остаётся полем текущего backend-контракта подбора; она не является оценкой всех навыков. Контракта подтверждённых тестовых результатов по отдельным навыкам пока нет.

Видимость профиля различает отключённый показ работодателям, доставку изменений и фактическую готовность в matching. Готовность читается через существующий `GET /api/candidate/pipeline`, только для текущей ревизии. Недостающие поля показываются простыми словами. Повтор неудачной доставки использует существующий endpoint без изменения ревизии; consent никогда не включается автоматически. PDF формируется из резюме, подбор использует его структурированные поля и описания.

Проверка причин подбора и индивидуальных уровней: `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs node tests/candidate-profile-readiness-browser.mjs` (выключенное согласие, готовность текущей ревизии, недостающие поля, повтор доставки).

## Чекбоксы редактора резюме

Рабочий формат, переезд и оба согласия используют общий native `Checkbox` из ui-kit: тот же внешний вид, фокус и клавиатурное управление, что у согласия на экране входа. Сохранение редактора доступно только при обеих отметках обработки и показа работодателям; submit дополнительно проверяет их до запроса. При повторном редактировании значения читаются из сохранённого профиля и не сбрасываются. Отдельное действие «Отозвать согласия резюме» доступно при уже сохранённых согласиях, независимо от локальных отметок. Оно требует подтверждения и использует тот же API профиля с текущей ревизией, пустыми fields и обоими согласиями false, также отзывая обучение. Оно не сохраняет несохранённые правки. Обычное сохранение остаётся заблокированным. Верхний отступ профиля уменьшен до 32rem на широком экране, на мобильном остаётся 24rem. Регрессия: `tests/candidate-browser.mjs` (состояния обеих отметок, submit, Space, ширины 1920/1024/390).

Ревизия исходного резюме и ревизия matching независимы: актуальная доставка проверяется по `projection.source_revision === revision`, а готовность matching — по `pipeline.profile_revision === projection.projected_revision`. Регрессия проверяет различающиеся номера 2 и 9.

При обеих отметках кнопка сохранения доступна. Submit показывает полный список недостающих обязательных полей подбора: имя, город, зарплатные ожидания, направление и общая категория опыта. Данные не отправляются, пока список не заполнен; остальные ограничения полей остаются в native validation и серверной проверке.
