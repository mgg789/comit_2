# Проверка текущей выборки и пробное обучение R₀

06.10.2026: выборка пригодна для проверки механики обучения; преимущество модели
для подключения к подбору будет оцениваться на полной выборке. Из сохранённого кэша обучен
отдельный `test_only` R₀; основной комбайн и активная модель не менялись.

## Что проверено

В кэше находятся 12 семейств и 119 принятых профилей: backend-01…08 и
frontend-01…04. Разбиение — 8 train / 1 validation / 1 calibration / 2 golden.
Остальные шесть направлений по протоколу добавляются следующими партиями. Это частичная выборка относительно
[протокола 60 семейств](../context/51-reranker-and-feed-learning.md).

531 попарная оценка содержит 511 решающих ответов, 7 ничьих и 13 ответов
«недостаточно данных». Из 119 отдельных оценок пригодности 105 имеют числовой
уровень, 14 — неизвестный. Учитель этой выборки: SystemOne `kev-latest`, prompt
`rerank-systemone-v1`. Новые диагностические ответы grounded Qwen v5 в обучение
не включались. Согласие с этим учителем не является независимой оценкой качества.

Точных дубликатов профилей и структурированных фактов между разбиениями нет.
В 10 из 12 семейств есть циклы попарных предпочтений. Точный перебор порядков
через ограниченное динамическое программирование показывает: любой скалярный
порядок неизбежно расходится минимум с 17 из 511 решающих меток. Это нижняя
граница противоречий, а не основание автоматически удалить все циклические метки.

Старые признаки относятся к прежней версии основного комбайна. Они не были
переименованы в новую схему: для десяти семейств вне golden признаки пересчитаны
из проверенных исходных фактов тем же runtime builder и сохранённым pinned
Harrier640. Все числовые значения и основные scores совпали, но совместимость
зафиксирована новым хешем схемы. Golden проверен по источникам, без построения
признаков для обучения и без прогнозов модели.

Проверены точные generation receipts: 7 старых локальных Qwen, 16 текущих
удалённых и один исторический Qwen v1. Исторический receipt допускается только
при чтении этого зафиксированного кэша; идентичность новых запросов не ослаблена.
Посторонние повреждённые ответы других пилотов не становятся источниками.

## Результат обучения

Train содержит 79 профилей и 335 решающих запросов; зеркальные разности дают
670 строк обучения, но не 670 независимых наблюдений. Нормализация рассчитана
только по train. Из 756 признаков 104 изменяются в train, 349 постоянны при
наличии сигнала, 303 никогда не наблюдаются. Учитываются отдельные маски отсутствия.

Проверена фиксированная сетка C = 0.01, 0.1, 1, 10. Выбор сделан только по
validation; выбран C = 0.01. Метрики всех четырёх вариантов сохранены в отчёте.
Calibration не использовался для выбора C или последующей подстройки. Выполнен
два запуска фиксированной сетки: исходный и воспроизведение после исправления
запрета одинаковых фактов с разными описаниями между разбиениями. Данные,
признаки, правило выбора, коэффициенты и метрики идентичны; подстройки по
calibration не было. Оба запуска консервативно учитываются в лимите двух циклов;
дальнейшая настройка этого probe запрещена. Хвост не калибровался и не отсекается.

| Выборка | NDCG@10 комбайна → R₀ | Попарная точность комбайна → R₀ |
|---|---:|---:|
| Validation, backend-05 | 0.9113 → 0.9751 | 65.12% → 81.40% |
| Calibration, backend-06 | 0.9966 → 0.9912 | 63.64% → 59.09% |

На validation результат лучше, но эта выборка участвовала в выборе модели.
На calibration преимущество не подтвердилось. Каждая из этих выборок содержит
только одно семейство: доверительные интервалы по семействам не определены.
Train macro NDCG вырос с 0.9540 до 0.9732; это результат на обучающих данных.
Micro-метрики, исходные scores, позиции и вклад признаков доступны в отчёте.
Порядок для метрик соответствует runtime: при равенстве R₀ используется основной
score, затем ID; базовый порядок при равенстве основного score использует ID.

20 golden-профилей оставлены закрытыми: прогнозов на них **0**. Полный golden gate,
независимая человеческая проверка и проверка отсечения — следующие этапы. Артефакт
имеет `test_only=true`, `promotion_eligible=false`, `tail_gap=null`; его нельзя
активировать. Score остаётся линейной оценкой порядка, не вероятностью найма.

## Воспроизведение и область применения

Из корня репозитория:

```bash
PYTHONPATH=services/matching-engine/src services/matching-engine/.venv/bin/python -m matching_engine.rerank_sample_probe
```

Изолированные manifest, производные признаки, модель и отчёт находятся в
`tests/artifacts/reranker/diagnostic-sample-probe-v2/` (git-ignored). Исходный v1
сохранён отдельно без изменений. Завершённый
запуск при повторе проверяет целостность и возвращает отчёт без переобучения;
изменение исходников, источников или контекста требует отдельной версии эксперимента.
Незавершённый receipt не разрешает неявно повторить подбор параметров.

[Сохранённый отчёт](../data/validation/rerank-current-sample-probe.json) содержит
хеши модели, исходников, источников и отчётов. Хеш модели:
`c69d57358a684c6c57273cb3e001b311905170028edeb8116b6708adceaccacc`.
При воспроизведении с запрещёнными функциями обучения, HTTP, чтения ключа и
Harrier inference вызовов было 0. Старые cache bytes и ledger 28/736/119 сохранены.
Новых расходов API не было.

Следующий учебный набор должен использовать единую исправленную версию учителя
с явными предпочтениями и покрыть все восемь направлений по исходному протоколу.
Повторное обучение на тех же старых метках не заменяет эту проверку. Качество реальных
предпочтений работодателей, production и полная приёмка обученного R₀ в backend
оцениваются отдельно от этого отчёта.

Проверки этого изменения: 56 целевых тестов; полный набор matching-engine с
PostgreSQL — см. актуальное число в сохранённом отчёте; scoped Ruff;
`pnpm typecheck`, `pnpm build`, `make smoke` — зелёные. Smoke проверил 12
контрактов настоящих локальных сервисов и существующего nginx. Отдельные
API-тесты не повторялись: API и его контракты этим изменением не затронуты.
