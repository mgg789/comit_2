# Кабинет работодателя (`apps/employer`)

> Статус (09.10): все экраны макета приведены к значениям Figma (артборд 1920), кроме
> пустого «Настройки»: вход, вакансии, страница вакансии с лентой, «Резюме», профиль
> кандидата, «Соискатели», чат, статистика, AI-агент; общий стартовый экран `/`
> (`apps/welcome`). Анимации — framer-motion. Макеты: Figma COMIT, секция
> «Работадатель» (node 771:1937), стартовый экран — node 770:1788.

## Запуск

```sh
npx -y pnpm@9.14.2 install                       # версия pnpm закреплена в package.json
npx -y pnpm@9.14.2 --filter @comit/web-employer dev   # http://localhost:5174/employer/
npx -y pnpm@9.14.2 --filter @comit/web-employer test  # vitest, чистая логика
```

Если глобальный pnpm новее (10+), он пытается скачать 9.14.2 по `packageManager` молча —
при медленной сети это выглядит как зависание; `npx pnpm@9.14.2` обходит это.

Если `npx pnpm … dev` зависает на старте (тот же эффект), Vite можно запустить напрямую:
`node apps/employer/node_modules/vite/bin/vite.js apps/employer`.

Dev-сервер проксирует `/api/*` на api-core (`API_PROXY_TARGET`, по умолчанию
`http://localhost:8080`) с отрезанием префикса — как nginx в `infra/nginx/nginx.conf`.
Для входа origin `http://localhost:5174` должен быть в `AUTH_ALLOWED_ORIGINS`.

## Устройство

Маршруты (basename `/employer`): `/vacancies`, `/vacancies/new`, `/vacancies/:draftId`,
`/resumes`, `/candidates`, `/candidates/:candidateId?vacancy=<draftId>`, `/chats/:processId`,
`/statistics`.

## Вход

`POST /auth/employer/code` → экран кода → `POST /auth/employer/verify` с
`consent: {processing: true, version: "account-v1"}` (галочка согласия обязательна до
запроса кода, [согласие](legal/processing-consent.md)). Код — 6 цифр (api-core
`OTP_LENGTH`; в макете 5 ячеек — следуем контракту). Ввод принимает автозаполнение
`one-time-code` и вставку целиком. Ошибки `role_mismatch`, `invalid_code`,
`challenge_expired/exhausted`, `resend_cooldown`, лимиты — показываются по коду `detail`.
Кнопка «Яндекс» из макета не выводится: OAuth-входа в api-core нет.

## Вакансии

Список читает все страницы `GET /employer/vacancies` (keyset, до 10×50). Статус:
`business_status=open` → «Активная», `draft` → «Черновик», `closed` → «Закрыта»,
плюс состояние публикации (`creating`, `failed`). ЗП «от–до» обязательна и показывается
всегда (ТЗ §2.2).

Публикация — существующий контракт из трёх шагов: создать черновик (или CAS-патч
с `expected_revision`) → `approve` → `publish` с `summary_hash`. Сбой после сохранения
оставляет черновик. Форма заполняет поля, которые требует `_missing` в agents-service:
название, направление (`class`), ЗП от/до (вводятся в тыс. ₽, хранятся в ₽), город,
формат, график (`daily`); описание (`bio`) — необязательно.

## Страница вакансии и лента

Левая колонка — данные и требования (вес 0…7 → «Обязателен/Важен/Средний вес/Желателен»),
«Понравились в ленте» (`GET .../saved`), «Назначенные собеседования» (интервью
`proposed/scheduled` из процессов вакансии). Правая — `FeedDeck`:

- `POST .../feed` открывает порцию; `404` (вакансия ещё не готова в matching) и `409 … not ready`
  (подбор строится) показываются как ожидание с автоповтором раз в 5 с;
- верхняя карточка подтверждается `feed/impressions` один раз, ключ переиспользуется при повторе;
- like/dislike — свайп, кнопки или ←/→; ключ идемпотентности привязан к exposure;
- `feed session expired` переоткрывает сессию; порция добирается по `next_cursor`.

Карточка показывает только серверное объяснение: процент = `explanation.score`, факторы
строгого фильтра (`filter_factors`), top matched features с уровнем и статусом
подтверждения, вклад каналов рейтинг/навыки/смысл, history badges, пометку
исследовательской пары гипотез. Фронт не пересчитывает скоринг.

## Найм

Действия на профиле кандидата (`?vacancy=`) строятся из `allowed_actions` процесса:
пригласить (компания, описание, обязательная вилка — по умолчанию из вакансии),
отклонить без приглашения (не видно кандидату), собеседование, итоги собеседования,
оффер, отказ с причиной. Каждая мутация несёт `expected_revision` и UUID-ключ.
Контакты запрашиваются только для `accepted/offer_sent/hired`
(`GET /employer/recruitment/:id/contacts`), до этого — подсказка, что они скрыты.

Чат: история через `after_sequence`, затем SSE `streamChatEvents` с переподключением по
курсору; `410` перечитывает историю. Вложения до 8 МиБ скачиваются файлом, не рендерятся.
Завершённый процесс — только чтение.

## Агент

Орб справа снизу открывает глобальный чат работодателя: история по `after_sequence`,
`POST /messages` ставит turn, статус опрашивается до завершения, сообщения дочитываются
каждые 5 с (фоновые отчёты). Пока оверлей открыт, отправляется presence heartbeat
(30 с; сервер считает отсутствие через 120 с). Показываются вопросы `pending-answers`
и расход бюджета за 7 дней. Если модель недоступна, новый turn не принимается —
показывается ошибка, ручные функции кабинета работают.

## Дизайн-система

Токены и Tailwind-тема — `packages/ui-kit/src/tokens.css` и `theme.css` (импортируются
всеми четырьмя приложениями). Все размеры — значения артборда 1920 в `rem`; на десктопе
(≥1024px) `1rem` растёт с шириной окна (16px при 1920, 12px при 1440), поэтому пропорции
совпадают с макетом на любом экране. Ниже 1024px база 16px и мобильные варианты вёрстки.

- Стекло: утилиты `glass`, `glass-card`, `glass-tab`, `glass-deck` — блик, светлый край,
  `backdrop-blur + saturate`; цвета и тени — токены.
- Шрифты самохостятся (офлайн-демо): Murs Gothic Wide Dark (заголовки), Inter Variable.
  Слово «COMIT» — векторный контур, экспортированный из Figma (`brand/wordmark.svg`).
- Иконки: экспортированные из Figma рендерятся CSS-маской (`currentColor`), остальные —
  lucide (`lucide-react`), как в макете.
- Компоненты: `Button` (`variant`/`size`/`shape` вместо классов-переопределений),
  `SelectField` (стилизованный listbox с клавиатурой вместо системного `<select>`),
  `ActionRow`, `MessageComposer`/`MessageBubble`, `Dialog`, `MatchBadge`, `CountBadge`.

## Анимации

`framer-motion` с пресетами в `packages/ui-kit/src/motion.tsx`: взаимодействия 150 мс,
появления 300 мс (AGENTS.md), единая кривая; `MotionRoot` учитывает системное
«уменьшить движение».

- переход между разделами, скользящая «таблетка» активного раздела в навигации,
  индикатор вкладок вакансий;
- каскадное появление списков (карточки, строки «Резюме» и «Соискателей», плитки,
  собеседования, секции профиля) и раскрытие секций по высоте;
- лента: перетаскивание карточки с наклоном и штампами «В шортлист»/«Пропустить»,
  бросок по скорости, улёт в сторону решения, подъём следующей карточки;
- диалоги, выпадающие списки, меню и уведомления появляются и исчезают;
- агент: затемнение, появление сообщений, пульсирующие точки «Агент думает»;
- кнопки — отклик нажатием (CSS `scale`, без JS).

## Локальный стенд для проверки

Полный стек поднимается overlay-ами из `docs/runbook.md` (без `auth-mail-worker` —
локально письма не отправляются). Для ленты нужна embedding-модель (runbook, шаг
`snapshot_download`) и кандидаты в пуле: их можно завести через настоящий API
(аккаунт по коду → `PATCH /candidate/profile` с согласиями `profile-v1`). Имена
в публичных карточках анонимны до принятия приглашения (ТЗ §2.2): UI показывает
«Кандидат 4EC3», реальное имя — только в контактах после принятия.
