## Реальный интерфейс и данные

В изолированном браузерном стенде с синтетической учётной записью пройдены еженедельное задание и привязка demo FSP; результат сохраняется после перезагрузки. На ширинах 1280 и 390 px проверены форма импорта, согласие и отсутствие горизонтального скролла. Отдельный браузерный проход PDF на 390×844 завершён: import200, preview, заполнение пустых города/описания без замены ручного имени, сохранение PATCH200 и reload. Невалидный PDF получил422 с понятной ошибкой; введённые поля сохранились. Ошибок JavaScript нет; fixture-only404 chat-unread не относится к product acceptance.

Импортированы 240 вымышленных резюме и 48 вакансий, повторный импорт идемпотентен, письма не отправлялись. Проверенный объём фактической публикации через Harrier/штатные workers и текущие очереди указан в [demo-data.md](demo-data.md) и [`acceptance.json`](../data/demo/acceptance.json). Число исходников не равно числу готовых карточек.

Локальный Jev вернул некорректное равномерное заполнение, поэтому подтверждены транспорт, кэш и безопасный отказ от сомнительного ответа, но не качество модели. Пользователь подтвердил, что production Jev будет другим; основной провайдер сохранён без DeepSeek fallback. Подробности: [vacancy-suggestions.md](vacancy-suggestions.md).

## Доработка тестирования и канонических навыков

Поверх `04b481e` добавлены широкие модальные окна, центральная кнопка полного
экрана, фиксированные навыки с именованными уровнями и действиями на каждой
карточке. Реальные PG-регрессии проверяют неизвестные координаты, старые записи,
точное соответствие результата навыку, удаление/возврат навыка и идемпотентное
восстановление проекций. Тесты профиля, weekly и истории также проходят без skips.
Общий typecheck/build проходит; testing UI — 14 тестов, ui-kit — 9 тестов.

Развёрнутые ответы проверены живым DeepSeek на синтетических данных: верный и
перефразированный ответы приняты, неверный отклонён. Ключ Jev в этой среде не
настроен; его адаптер покрыт контрактными тестами, живой вызов здесь не заявлен.
Сбои проверки не считаются ошибкой кандидата, а исходный отправленный ответ
восстанавливается после обновления страницы и доступен для повторной отправки.
Production проверяющий VM этим проходом не разворачивается: требования к его
границе и подключению описаны в [deploy.md](deploy.md#изолированная-проверка-кода).


Финальные backend gates новой правки: testing-engine — 37 passed, 80,69% строк /
69,69% ветвей (порог 75/60); code-judge — 13 passed, 93,33% / 81,25%
(порог 80/60). Отдельная реальная Docker-проверка проходит негативные сценарии.
Настоящий HTTP-путь testing-engine → broker → Docker проверен для Python и
алгоритмов: первым приходит MCQ, вторым — code, верный ответ принимается,
следующий вопрос имеет answered=2. Перезапуск движка сохраняет второй вопрос,
повтор ответа не увеличивает счётчик. Проверка HTTP broker также подтвердила
