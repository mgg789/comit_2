# Testing engine — механика тестирования

> Статус на 11.10.2026: адаптивный браузерный контур работает для семи семейств,
> с реальной серверной проверкой MCQ и коротких ответов, записью по согласию,
> восстановлением попытки и публикацией предметного грейда. Код и развёрнутые
> ответы требуют отдельного работающего судьи и не выдаются кандидату.
> [Целевой дизайн](testing-design.md), [канон](../context/60-testing-engine.md).
> Ранние планы ниже сохранены для контекста; актуальная реализация описана
> в разделе браузерного контура.

## Две анти-цели ТЗ и наш ответ

| Проблема ТЗ | Решение |
|---|---|
| Единый набор заданий → утечка | **Blueprint'ы**: один шаблон = семейство задач; сидированная генерация бесконечных вариантов с калиброванными диапазонами параметров |
| Нейрогенерация под каждого → несопоставимая сложность | Сложность зашита в шаблон (`difficulty.base/discriminative`), а не в генерацию; LLM не пишет задания в MVP |

## Компоненты

- `blueprints/*.yaml` — шаблоны (специализация, тема, тип: code|quiz|approach, параметры, сложность).
- `src/testing_engine/blueprints.py` — реестр: загрузка, валидация, выбор; API: `GET /blueprints`, `GET /blueprints/{id}`.
- Дальше (S2): генератор вариантов по сиду, песочница исполнения кода (контейнер без сети, таймауты), адаптивный грейд-тест (confirmed | offered-lower | offered-higher), cooldown смены грейда (3 месяца, настраиваемый).

## Правила грейд-теста (ТЗ)

- Грейд не понижается принудительно; не прошёл — тест на уровень ниже; прошёл уверенно — предложение повысить.
- Смена грейда ограничена по времени (дефолт: раз в 3 месяца); история попыток видна кандидату.
- Категория (специализация × грейд) присваивается ТОЛЬКО тестом.

## Валидация тестирования (обязательна к сдаче)

1. Test-retest: повторное прохождение (новые варианты тех же blueprint'ов) → стабильный грейд.
2. Дискриминативность: синтетические слабые/сильные сессии → разделяет ли скор классы.
3. Экспертная разметка: N=30 решений вручную → совпадение с автоскором.
4. Утечка: «слитый» вариант не решает следующий вариант того же семейства.

Каждый пункт — с числами в документации сдачи (критерий №2 — 25% оценки).

## Браузерный контур и приватность (2026-10-11)

Браузер обращается только к `/api/candidate/testing/*`. API проверяет кандидатскую сессию и origin мутаций, передаёт сервисный токен и ID владельца в приватный testing-engine. До нажатия «Начать» preflight не создаёт попытку. Доступны только реальные семейства банка: algorithms, sql, rest_api, python, react, docker, teamwork; общий тест направления из этих результатов не имитируется. Максимум 30 вопросов. Повторное чтение возвращает текущий неотвеченный вопрос; правильные ответы, скрытые тесты и рубрики браузеру не передаются.

Старт требует `testing-media-v1` и согласия на запись экрана. Реальная загрузка видео включается `TESTING_RECORDING_MODE=full`; preflight сообщает recording_enabled, при выключенной записи сохраняются только агрегаты. Камера добровольна; без отдельного согласия webcam-чанки запрещены. Согласие с серверным временем сохраняется в попытке и manifest записи. Чанки ограничены 3 млн символов base64, суммарно 512 MiB на попытку; одинаковые номера и байты допускают безопасный повтор. Записи удаляются по manifest через 90 дней: проверка при старте сервиса и каждый час.

После последнего ответа клиент завершает загрузки, отправляет итоговую supervision и вызывает `/finish`. Только затем публикуется подтверждённый результат с итоговым бейджем. Пока публикация не подтверждена, результат не обозначается как записанный в профиль. `/abandon` сохраняет прерывание без публикации грейда и вводит семидневную паузу для того же семейства. Подтверждённые семейства сохраняются отдельно (`grade:<family>`), не переписывая общий заявленный грейд кандидата. Пересдача — через 7 дней, повышение — через 30 дней; preflight также учитывает результаты API.

Короткие текстовые ответы (`short_answer`) проверяются детерминированно по серверному списку допустимых значений после нормализации пробелов и регистра. Дополнительные семь заданий дополняют существующий банк, не запускают код и не передают эталоны браузеру. Код требует внешнего CODE_JUDGE_URL; без него сохраняется без оценки. Развёрнутые ответы требуют ручной оценки и не влияют на автоматически подтверждённый грейд.

Браузерный контур выдаёт только полностью автоматически проверяемые MCQ и short_answer (preflight сообщает supported_question_types). Неоценённые code/extended не смешиваются с пользовательской подтверждённой попыткой. Контур legacy judge сохраняется отдельно. Подтверждённый отказ от камеры виден работодателю в актуальном защищённом профиле; старое отсутствие metadata обозначается отдельно как unknown.


### Граница доверия к наблюдению

Браузерные счётчики — недоверенные сигналы, а не доказательство отсутствия
нарушений. Сервер привязывает их к владельцу, ограничивает длительность временем
попытки, запрещает уменьшение checkpoint и сохраняет отказ от камеры. Это не
исключает подмену клиентского JavaScript. Работодатель видит автоматическую
отметку присутствия с явным пояснением; вывод о честности автоматически не делается.
При разрешённой полной записи материалы предназначены для отдельной ручной
проверки, а не публичного доступа. Режим записи фиксируется при создании попытки:
последующее включение env не меняет согласия уже начавшего тест кандидата.


### Браузерная регрессия

`apps/testing/tests/browser-acceptance.mjs` проверяет квадратные чекбоксы
(1440/390 px), возобновление той же попытки с записью, сохранённые счётчики,
повтор после потери ответа и прерывание без грейда. Использует только
`startTestingBrowserFixture` (`apps/api/tests/helpers/testing-browser-fixture.ts`)
с аккаунтом `selftest@example.invalid` и виртуальные устройства Chrome.
Нужны запущенные fixture и UI, приватный storage state после dev-входа:

```sh
TESTING_FIXTURE_METADATA=/private/tmp/testing-fixture.json \
TESTING_STORAGE_STATE=/private/tmp/testing-state.json \
TESTING_UI_URL=http://127.0.0.1:5185 \
node apps/testing/tests/browser-acceptance.mjs
```

Playwright должен быть установлен отдельно; `PLAYWRIGHT_MODULE` позволяет
указать путь к его ESM-модулю. Метаданные содержат `apiUrl`, `engineUrl`,
`email`, `mediaDir`, созданные fixture. Состояние авторизации хранить с правами
600, не коммитить. Тест расходует синтетическую попытку Python; повторный
полный запуск выполняется на новом fixture. Это отдельная браузерная проверка,
не часть unit-команды и не проверка физических камеры/телефона.
