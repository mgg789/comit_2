# Предзарегистрированный сложный бенчмарк R₀ (rerank-hard-benchmark-v1)

> Статус: неймспейс `rerank-hard-benchmark-v1`, ветка `feat/ml-reranker-improvement`.
> Только оценка: ни одно семейство бенчмарка не может использоваться в обучении,
> активация продолжает требовать закрытые gates и слепые проверки.
> Мотивация: [итог расширенной выборки](rerank-grounded-cohort-acceptance.md).

## Зачем

Закрытый grounded-корпус не способен подтвердить требуемый выигрыш NDCG даже
идеальному порядку: main даёт NDCG = 1.0 в восьми из двенадцати golden-семейств,
теоретический потолок macro-прироста — **0.004110** против порога активации **0.02**.
Приёмка прямо фиксирует: нужен новый независимый, заранее зафиксированный
бенчмарк со сложными альтернативами. Этот неймспейс — такой бенчмарк.

## Что сделано

1. **Предрегистрация до разметки.** 12 семейств (backend/frontend/data/ml ×
   mixed / class_only / stack_only|domain_only|domain_heavy) зафиксированы
   манифестом с хешем `5c68f11a…` **до первого учительского вызова**: сценарии
   вакансий, политики из того же набора из 8 baseline-приоритетов, что и при
   обучении R₀, кандидаты, main-скорa, гейт сложности, протокол оценки.
   Артефакт под тестом (упакованный `r0-c18f4bc1`) зафиксирован в манифесте
   тоже до разметки — отбор семейств никак не зависит от артефакта.
2. **Сложность гарантирована конструкцией, а не выборкой.** Пробный раунд
   субагентной генерации дал только 1–5 близких пар из 21 на семейство: LLM не
   умеет оптимизировать близость weighted-скоров. Поэтому матрицы фактов строит
   детерминированный дизайнер (`tests/artifacts/benchmark-staging/design_matrices.py`,
   seed 42): комбинации (δ уровня, статус подтверждения) берутся из одного
   точного класса равной взвешенной суммы и равной суммарной дельты уровней —
   weighted main их не различает, а лексикографическая политика учителя может.
   Результат гейта на реальном оракуле (build_family_features, настоящий
   Harrier): **close_pairs 9–21 из 21 при preregistered минимуме 8, span ≤ 0.14**.
3. **Субагент отвечает за поверхность.** Русские описания (84 шт) написаны
   внешним текстовым субагентом (glm-5.3-flash, fallback по прямому указанию
   Mike; Qwen-субагент в harness недоступен) с жёсткой факт-согласованностью.
   Происхождение честно записано в манифесте: `external-subagent-glm-5.3-flash`,
   сырые выходы сохранены, вызов Sverk-генерации не выполнялся, generation-бюджет
   не потрачен.
4. **Разметка — штатным учителем.** Пары и независимые suitability-оценки идут
   через общий `CohortProviders` (SystemOne `kev-latest`), общий кэш и
   кумулятивный ledger, с durable per-attempt receipts и одним repair-попыткой.
   Пилот из 8 предзарегистрированных случаев (16 направленных пар + 8 грейдов)
   обязан пройти полностью до разметки семейств.
5. **Бюджет.** По прямому решению Mike (2026-10-07) потолок grade поднят
   600 → 700 (`BENCHMARK_LIMITS`, коммит-тело фиксирует решение); кумулятивный
   ledger не сбрасывался: ожидаемый расход бенчмарка — ≤288 pair и ≤84 grade
   сверх ledger_before. Generation остался 120/120 (внешняя генерация его
   не расходует).

## Оценка: результат (12 семейств, 218 решающих пар)

Разметка завершена 07.10.2026 в неймспейсе `rerank-hard-benchmark-v7`
(ledger после: pair 2836/3000, grade 699/720). Оценка упакованного артефакта
`c18f4bc1` против main — те же формулы, что `rerank_training.evaluate`:

| Метрика | Main | R₀ (c18f4bc1) | Δ |
|---|---:|---:|---:|
| Macro NDCG@10 | 0.9870 | 0.9978 | **+0.0107** |
| Macro pair accuracy | 0.6299 | 0.6351 | +0.0052 |
| CI low (paired family bootstrap) | — | — | 0.0 / −0.091 |
| Oracle headroom (идеальный порядок) | — | — | **+0.0130** |

Интерпретация, включая неприятное:

- На сложном бенчмарке ΔNDCG упакованного R₀ **вчетверо выше**, чем на лёгком
  golden v9 (+0.0107 против +0.0026): на близких альтернативах артефакт
  упорядочивает лучше main; абсолютный macro NDCG 0.9978.
- Но pair accuracy на сложных парах падает до 0.635 (на лёгком golden 0.959):
  попарный сигнал R₀ **не обобщается** на вот эти близкие вызовы; CI pair-прироста
  уходит в минус (−0.091). Swap-аудиты учителя 26/36 (на v9 — 129/132) подтверждают:
  именно эти пары шумны для учителя; 4 семейства помечены quarantined
  (backend-hard-1/3, data-hard-3, ml-hard-3 — по 1/3 реверсов).
- **Oracle headroom 0.0130 < 0.02** — даже идеальный порядок не прошёл бы
  NDCG-порог. Причина структурна: при близких main-скорах кандидаты одного
  грейда получают близкие suitability-грейды, listwise-потолок NDCG остаётся
  низким при высокой pairwise-сложности. Рычаг следующей итерации дизайна:
  сценарии, где weighted main ошибается содержательно — `self_reported`-грейд
  (штраф 0.6 в main при нормальной suitability у учителя) и семантический
  ввод в заблуждение при bio (frontend-hard-1: baseline NDCG 0.844,
  headroom 0.156 — единственное такое семейство).
- `passed=false`: активация не открыта. Promotion по-прежнему требует закрытые
  gates на sealed-корпусе и 20+20 слепых проверок — user20 ждёт Mike:
  `rerank-grounded-pair-repair-v4/reviews/user-packet.md`.

Итог для оператора: бенчмарк валиден как измерительный инструмент
(предрегистрация, изоляция, воспроизводимость), но порог 0.02 NDCG@10 в текущей
формулировке gate недостижим ни на лёгком, ни на сложном наборе одного грейда —
калибровка порога выносится на решение Mike вместе с результатами выше.

Отчёт с хешами: `rerank-hard-benchmark-v7/evaluation.json`
(report_hash `6181a554…`, dataset_hash `7cb99549…`).

## Команды

```sh
cd services/matching-engine
PYTHONPATH=src .venv/bin/python -m matching_engine.rerank_hard_benchmark status   # состояние
PYTHONPATH=src .venv/bin/python -m matching_engine.rerank_hard_benchmark ingest \
  --directory tests/artifacts/reranker --staging tests/artifacts/benchmark-staging
PYTHONPATH=src .venv/bin/python -m matching_engine.rerank_hard_benchmark label    # пилот + разметка
PYTHONPATH=src .venv/bin/python -m matching_engine.rerank_hard_benchmark evaluate
```

Артефакты неймспейса живут в локальном ignored-каталоге
`tests/artifacts/reranker/rerank-hard-benchmark-v7/`; в Git попадают только
код, тесты, документация и версионируемые отчёты.

## Честные границы

- Синтетика: бенчмарк измеряет соответствие политике учителя, а не реальные
  предпочтения работодателей.
- Бенчмарк не «обучающий»: обучение на нём запрещено манифестом; если позже
  понадобится train-расширение — это отдельный неймспейс с собственной
  предрегистрацией.
- Близость обеспечена конструкцией матриц; поверхность (описания) — субагентная.
  Изоляция от v9 проверена по точным фактам и нормализованным описаниям.
- Семейства частично вырождены в точные tie по main-скору (например ml-hard-1:
  все 7 скор равны) — это сознательная часть дизайна: main не может упорядочить
  такие альтернативы в принципе.
