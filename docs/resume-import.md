# Импорт резюме

Первый необязательный шаг редактора кандидата принимает PDF, PNG, JPEG и WebP. После отдельного согласия файл обрабатывается локально, без отправки во внешние ИИ-сервисы. Показан исходный распознанный текст; кнопка заполняет только пустые поля. Сохранение и публикация происходят через обычный редактор и его проверку ревизии.

`POST /api/candidate/profile/import` принимает `{filename, content_base64, processing_consent: true}` под сессией кандидата и проверкой Origin. Ответ: `{fields, extracted_text, method, warnings}`. Авторизация внутреннего `POST /internal/candidate-resume/parse` использует токен сервиса и владельца из сессии. Результаты и ошибки имеют `Cache-Control: no-store` на внешнем API.

PDF извлекается pypdf; страницы без текстового слоя и фотографии — Poppler/Tesseract (`rus+eng`). Контейнер agents-service содержит необходимые утилиты. Ограничения: 5 МБ, 10 страниц, 20 млн пикселей на изображение, 100 000 символов; отдельный процесс с лимитами CPU/памяти и 45-секундным таймаутом. Временные файлы удаляются после обработки. Документы не сохраняются, не передаются в фоне и не попадают в логи — так задумано для приватности.

Парсер переносит явно указанные имя, город, телефон, направление, заявленный грейд и разделы опыта/проектов/достижений. Незнакомое оформление сохраняется в полном тексте и поле «О себе». Разделы опыта сохраняются как один редактируемый блок: пользователь уточняет организации и периоды. Уровни навыков не угадываются, доказательства, ФСП и подтверждённые грейды никогда не создаются. Импорт не меняет email учётной записи.

Если в окружении нет OCR-утилит или языковых данных, пользователь получает понятное сообщение и продолжает ручным вводом. Поддержка HEIC, защищённых PDF и более длинных документов — в плане развития. Качество OCR зависит от снимка, поэтому предпросмотр обязателен.

## Проверка полного HTTP-пути

`pnpm --filter @comit/api exec tsx --test tests/candidate-resume-import.test.ts` проверяет границы доступа и настоящий путь API → отдельный agents-service → дочерний процесс pypdf. Текстовый PDF собирается тестом с корректной таблицей смещений; проверяются имя, город, направление, заявленный грейд, опыт и ошибка повреждённого PDF. Транспорт парсера в этом acceptance не подменяется.

Для запуска нужны зависимости `services/agents-service`; переменная `TESTING_ENGINE_TEST_PYTHON` выбирает интерпретатор, по умолчанию `python3`. Runtime обязателен: тест завершается ошибкой, а не пропускается. Процесс сервиса запускается без внешних ключей/БД и останавливается после теста. OCR отдельно проверяется в образе agents-service с Poppler и Tesseract.
