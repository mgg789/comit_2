# Привязка демо-ФСП в кабинете кандидата

В сохранённом резюме блок ФСП проверяет `GET /api/candidate/profile/fsp/status`. Только при `NODE_ENV=development` и `FSP_DEMO_ENABLED=true` появляется кнопка подключения демонстрационного аккаунта. Подключение реального реестра ФСП — следующий этап; профиль без истории ФСП — нормальное состояние.

1. Кандидат выбирает один из учебных аккаунтов. Уже привязанный аккаунт можно обновить, но сменить без отдельной отвязки нельзя.
2. `POST /api/candidate/profile/fsp/demo/authorize` создаёт существующее одноразовое состояние, привязанное к кандидату, ревизии резюме и выбранному аккаунту (120 секунд).
3. Кандидат отдельно разрешает импорт достижений.
4. `POST /api/candidate/profile/fsp/demo/approve` принимает `{expected_revision, state, import_consent: true}`. API проверяет владельца и состояние, получает одноразовый код у integration-engine и выполняет существующий защищённый обмен. Код не попадает в браузер или URL.
5. Обычная атомарная процедура импорта проверяет ревизию, погашает состояние, переносит достижения без дубликатов и запускает обновление представления резюме. UI показывает обновлённый профиль и пометку демо-реестра.

Существующие JSON authorize/callback API сохранены для интеграционных клиентов. Флаги production не изменены. Произвольные FSP ID, чужие состояния, повторное подтверждение и просроченные состояния не принимаются. UI использует обычную сессию кандидата и проверку Origin; ни пароли ФСП, ни реальные внешние персональные данные не запрашиваются.

## Проверка реального HTTP-контракта

`apps/api/tests/candidate-verification-routes.test.ts` использует отдельную PostgreSQL БД из `VERIFICATION_ROUTE_TEST_DATABASE_URL` (или `FSP_TEST_DATABASE_URL`) и сам запускает integration-engine на свободном loopback-порту. Внешний тестовый реестр не нужен. Проверяются импорт, согласие, Origin, чужой владелец, повторное использование состояния и отсутствие дубликатов. Без БД запускаются только прочие unit-тесты; полный coverage gate предоставляет изолированную БД и запрещает пропуски.

Python выбирается через `TESTING_ENGINE_TEST_PYTHON`, по умолчанию `python3`; необходимы FastAPI, Pydantic и Uvicorn из зависимостей сервиса. Отсутствие runtime завершает acceptance ошибкой. Дочерний процесс останавливается после теста.
