# ADDITIONAL — сверх обязательного ядра

Обязательные требования не дублируются здесь: [CORE](core.md), [ТЗ §6.6](../context/tz/00-fsp-tz-2026.md).

| Возможность | Реализация | Статус и развитие |
|---|---|---|
| Безпарольный вход | [auth.md](auth.md): email + одноразовый код (OTP живёт 10 минут, HMAC-хранение, rate-limit) — паролей нет вообще | OAuth через Яндекс — в ближайшем мердже (миграция `022_yandex_oauth.sql`); роль фиксируется при входе, повторный запрос отменяет предыдущий код |
| Недельные мини-задания | [weekly-challenges.md](weekly-challenges.md), 3 параметризованных вопроса, серверный итог, один бонус до следующего понедельника | Практика платформы и сигнал активности; редактор заданий работодателя и защита от нескольких аккаунтов — следующий этап. Грейд подтверждается отдельным тестом |
| PDF/фото → анкета | [resume-import.md](resume-import.md), pypdf/Tesseract, предварительный просмотр, ручная правка | Распознанный текст проверяется кандидатом в предпросмотре. Уровни навыков и подтверждения задаёт сам кандидат и проверки платформы |
| Скачивание PDF-резюме | Автогенерация стандартизированного PDF-профиля: `GET /candidate/resume.pdf`; работодателю PDF открывается только после принятия приглашения ([candidate-profile.md](candidate-profile.md)) | Обезличенные и публичные карточки без PDF — правила видимости ТЗ §2.2 соблюдены |
| Автоопределение стека и уровней (решающая модель Jev) | [vacancy-suggestions.md](vacancy-suggestions.md): черновик вакансии обогащается стеком и уровнями hard/soft, durable jobs и cache, защита ручных изменений | Транспорт и кэш проверены на локальной модели; оценка качества на production-Jev — следующий этап. Сомнительные ответы отклоняются, доступно ручное заполнение |
| Оценка описания вакансии и близость ЗП к рынку | Индикатор объёма описания в редакторе (красный/жёлтый/зелёный — [vacancy-suggestions.md](vacancy-suggestions.md)); подсказка под вилкой вакансии «Ниже рынка / Средняя по рынку / Выше рынка» ([employer-statistics.md](employer-statistics.md)); кандидатский блок «Рынок З/П» — отдельная пока не подключённая функция | Текущая подсказка использует внешние медианы; замена на среднее опубликованных вилок платформы по грейду, направлению и стеку выполняется отдельно. Кандидатский блок честно показывает «данные недоступны». Смысловое качество текста моделью не оценивается |
| Рекомендательная лента | Discovery-лента работодателя: карточки с объяснением попадания, добор из резерва того же rerank-run ([feed-refill.md](feed-refill.md), [feed-change-policy.md](feed-change-policy.md)) | Исследование гипотез встроено в ленту дозированно (2 research-карточки на 18 обычных) |
| Подстройка под предпочтения работодателя | Preference-модель обучается на реальных свайпах владельца вакансии ([preference-learning.md](preference-learning.md)) | Сходимость ~20 реакций измерена на синтетических работодателях ([preference-convergence.md](preference-convergence.md)) |
| Демо-каталог | [demo-data.md](demo-data.md): 240 кандидатов, 48 вакансий, 16 компаний | Вымышленные помеченные данные, без рассылки писем и с честными статусами проверки. Публичные карточки и embedding строятся workers из этих источников |
| Чаты и уведомления | Диалоги найма на QGramm с шифрованием сообщений и вложений + системный Comit inbox с unread-счётчиками | Реальные сессии и роли; интеграция с QGramm проверяется отдельным acceptance-сценарием на живом сервисе |
| Служба поддержки | Системный чат Comit в обоих кабинетах + консоль оператора на `/support/` (вход email + access key): [support-console.md](support-console.md), [system-inbox.md](system-inbox.md) | Живой цикл «пользователь ↔ оператор» от имени Comit проверен browser-E2E |
| Автономный агент найма | [agents.md](agents.md): глобальный агент работодателя — один чат на аккаунт, фоновые поручения через `organization-agent-worker`, офлайн-дублёр отвечает за владельца в его отсутствие | Работает без присутствия пользователя на платформе — аналог агент-режимов ChatGPT/Grok; приёмка — [organization-agent-acceptance.md](organization-agent-acceptance.md) |
| Сроки найма и обратная связь | Рабочие дни, напоминания, отказ с ОС, агрегация рекомендаций | Качество обратной связи оценивает служба поддержки — осознанный выбор в пользу человеческого решения |
| Рекомендации кандидату | [recommendations.md](recommendations.md): недельные персональные рекомендации из наблюдений фильтров (почему редко попадает в ленты) и категорий причин отказов работодателей | Агрегация ОС с порогами приватности (≥3 процесса и ≥3 работодателя); честные состояния ready / insufficient_data / provider_unavailable |
| Назначение собеседований | Встречи внутри процесса найма: предложение, подтверждение кандидатом, SLA-пауза на время встречи ([recruitment.md](recruitment.md)) | Отмена процесса закрывает незавершённые встречи; таймлайн в рабочих днях |
| Детальная статистика | [employer-statistics.md](employer-statistics.md): воронка delivered → … → hired со сравнением периодов + журнал расходов | Читается из durable-реестра операций, а не с экрана; период 1–90 дней |
| Расходы | Журнал размещений, инвайтов, использования ИИ сверх нормы и неустоек | Учёт операций ведётся в журнале; подключение платёжного шлюза — в плане развития |
| Экономическое доказательство концепции | [economics.md](economics.md): LTV/CAC ≈ 12×, окупаемость CAC ~1,6 мес, безубыточность на 15-м месяце, сценарии чувствительности | Живые формулы в [economics-model.xlsx](economics-model.xlsx); рыночные бенчмарки — из открытых источников |
| Защита недобросовестного найма | Сроки, обязательная обратная связь, исторические действия; [концепция анти-фрода](anti-fraud-and-ats.md) | Расширенная модерация работодателей и антифрод — следующий этап |
| ATS и реальный ФСП ID/Keycloak | [Концепция интеграции](anti-fraud-and-ats.md), точки расширения outbox api-core; Keycloak-совместимость — [integration.md](integration.md) | Точки интеграции подготовлены; подключение внешних систем — в плане развития |
| Мобильная версия | Адаптивные формы и основной UI | Следующий этап — проверка на физических мобильных устройствах, включая захват экрана |
