# Совместимость нумерации миграций matching

После `011_candidate_showcase.sql` следует `012_hypothesis_exploration.sql`.
У файлов разные числовые версии; runner отвергает новые дубли до выполнения SQL.

Ранее hypothesis-файл назывался `011_hypothesis_exploration.sql`. Его SQL
сохранён без изменения байтов. При обновлении существующей БД runner проверяет
контрольную сумму исторической записи и добавляет каноническую запись `012`,
не повторяя DDL. Старую запись сохраняет для аудита. Несовпадение любой
контрольной суммы блокирует миграцию и откатывает текущую транзакцию.

Новая БД применяет только канонические имена. Миграции выполняются явной
командой `python -m matching_engine migrate`; запуск HTTP-сервиса их не применяет.

Регрессионная проверка `test_legacy_duplicate_version_alias_never_replays_sql`
создаёт историческую запись, проверяет отсутствие повторного SQL и отказ
при повреждённой контрольной сумме. Обычная проверка миграций также проверяет
повторное применение и изменение уже применённых файлов.
