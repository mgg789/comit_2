# Демонстрационный каталог

`data/demo/catalog.py` создаёт 240 вымышленных резюме, 16 компаний и 48 вакансий. `catalog.json` — воспроизводимый снимок генератора. Восемь направлений, три заявленных грейда, десять городов, разные зарплаты, форматы работы, продукты, стек и опыт. Генератор и импорт подготовлены отдельным агентом в рамках задачи наполнения.

Каждое резюме и вакансия явно помечены как демонстрационные. Контакты используют зарезервированный домен `.invalid`; телефонов нет. Достижения, тестовые грейды, реальная верификация, офферы и найм не фабрикуются. `email_verified` синтетической учётной записи — техническое условие демонстрационного контура, а не утверждение о доставке почты; происхождение аккаунта хранится в `processing_consent_version=comit-demo-2026-v1`. Согласие на обучение выключено.

## Безопасный запуск

По умолчанию программа только показывает объём, без базы и сети:

```sh
python data/demo/seed.py
```

Применение требует заранее мигрированной **отдельной локальной** базы `comit_demo_*`, точного `--target` и `--apply`. Значение `DATABASE_URL` задаёт оператор вне Git. Базы с недемонстрационными аккаунтами запрещены. Никакие production-флаги или серверы скрипт не меняет.

```sh
export PYTHONPATH=services/matching-engine/src:services/agents-service/src
# DATABASE_URL настроен приватно; имя базы должно совпасть с --target.
python data/demo/seed.py --apply --target comit_demo_preview
```

Для короткой проверки можно добавить `--sample 3`: создаются три резюме и одна вакансия. Повторный запуск использует стабильные UUID аккаунтов и ключи вакансий. Существующие резюме/вакансии не перезаписываются; авторские изменения сохраняются. Скрипт не генерирует OTP, не создаёт писем, приглашений, диалогов и платёжных событий.

Кандидаты проходят настоящий `ProfileStore.save` и очередь проекции. Вакансии проходят `Store.create` → approve → submit с неизменяемым summary hash. Сразу после импорта это **источники и очереди**; витрина наполняется по мере обработки workers.

## Публикация

Для полного запуска нужны установленные зависимости обоих Python-сервисов, Node/pnpm, работающий локальный matching API и заранее скачанный **точный Harrier snapshot**, указанный в `matching_engine.embeddings`. `MATCHING_ENGINE_URL` и внутренний токен задаются приватно.

```sh
python data/demo/seed.py --apply --target comit_demo_preview --process
```

`--process` запускает штатную проекцию API, публикацию agents-service и настоящие candidate/vacancy workers. Все векторы настоящие, проверка готовности не обходится. Если модель или провайдер ещё не доступны, данные ждут в устойчивой очереди, а команда сообщает об этом кодом ошибки. CPU-обработка полного каталога занимает несколько минут (см. замеры ниже). Можно использовать обычные контейнерные workers против той же отдельной базы вместо локального Python с моделью.

Финальный JSON отдельно показывает `candidate_pipeline`, `vacancy_pipeline` и `published_candidates`; готовность не подменяется числом импортированных строк. При ошибке не очищайте тома: изучите безопасные коды ошибок штатной очереди, восстановите зависимости и повторите обработку. Возобновление не создаёт дубликатов.

## Проверки

```sh
python -m pytest tests/fixtures/test_demo_catalog.py -q
```

Проверяются детерминизм, 240 уникальных имён/UUID, разнообразие направлений и городов, зарплатные вилки, отсутствие поддельных доказательств, совпадение JSON с генератором и запрет неявной/удалённой записи. Изменения каталога требуют повторной генерации `catalog.json` из `build_catalog()` и проверки теста. Синтетические данные предназначены для демонстрации; независимая оценка качества подбора строится на отдельной разметке ([matching.md](matching.md)).

## Проверенный локальный проход

Санитизированная квитанция: [`data/demo/acceptance.json`](../data/demo/acceptance.json). В изолированной локальной БД созданы и полностью опубликованы **240 резюме, 16 компаний и 48 вакансий**. Все 240 кандидатов и 48 вакансий подтверждены через настоящий публичный API 11 октября 2026 года в 02:06:53 UTC: пройдены все страницы по 50 карточек, дубликатов нет, проверки актуального согласия и публикации не обходились.

Итоговые состояния: кандидаты — 240 `ready`, вакансии — 48 `ready`; соответствующие 240 и 48 заданий — `completed`. Незавершённых заданий и записанных ошибок нет. Повторный импорт ранее создал 0 профилей; максимальная ревизия источников осталась 1, исходящих писем и подтверждённых доказательств — 0. Прежние зависшие аренды восстановились штатным worker; ручное изменение статусов и поддельные векторы не применялись.

Полный проход выполнен на CPU хоста в отдельном временном окружении с объявленными `matching-engine[embeddings]` зависимостями и двумя потоками. Использован точный существующий снимок Harrier `31de22b673913c7d658c0f03f792d77c2dcf8ebd`; загрузки моделей отключены. После проверки трёх заданий за 8,3 секунды оставшиеся 226 кандидатских заданий обработаны за 305,37 секунды, 47 вакансий — за 39,63 секунды.

Предыдущие попытки внутри Docker останавливались SIGKILL из-за давления на память Docker VM: пик cgroup был 933 609 472 байта (меньше 1 ГиБ) при лимите 5 ГиБ, `max=0`, `oom=0`, `oom_kill=5`. Это не переполнение собственного лимита 5 ГиБ. После переноса инференса на хост и восстановления PostgreSQL полный проход завершился успешно. Эта диагностика сохранена в квитанции как история; текущий проход проходит штатно.

После проверки workers завершились, собственные вспомогательные matching/agents API остановлены. Demo matching-контейнер сохранён остановленным; БД и данные не удалены. Глобальные Python-пакеты и чужие процессы не менялись. Проверен отдельный локальный каталог; production-наполнение не выполнялось.
