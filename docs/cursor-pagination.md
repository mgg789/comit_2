# Продолжение списков через cursor

Cursor является ключом продолжения в исходном хранилище. Gateway не оборачивает offset в base64 и не вычисляет псевдопозицию.

| Список | Продолжение |
|---|---|
| Вакансии `/employer/vacancies` | `next_cursor`, immutable `(created_at,draft_id)` в agents store |
| Процессы `/candidate/recruitment`, `/employer/recruitment` | `next_cursor`, immutable `(created_at,id)` в API store |
| Процессы одной вакансии `/employer/vacancy-drafts/:id/recruitment` | Тот же механизм, cursor привязан также к vacancy draft |
| Уведомления `/candidate\|employer/recruitment-events` | `next_sequence` → `after_sequence`, keyset журнала |
| SSE чата и уведомлений | `Last-Event-ID` или `after_sequence` |
| Saved/visited | `next_cursor` из matching-сервиса → query `cursor`; gateway передаёт без изменения |
| Витрина соискателей | Собственный cursor с проверкой актуальности пула, без изменений в этом проходе |

`limit` и прежний `offset` сохраняются. При продолжении через cursor нужно передавать `offset=0` либо не задавать offset. Новый SDK принимает cursor; старые вызовы без него продолжают работать.

Cursor процессов подписывается HMAC секретом авторизации и привязывается к роли, аккаунту и выбранному draft. Повтор через другой экземпляр API с тем же секретом допустим; перенос другому работодателю, смена фильтра/роли и изменение подписи дают 409. Ротация секрета инвалидирует ранее выданные cursors. PostgreSQL timestamp передаётся с исходными микросекундами: преобразование через JavaScript Date для ключа продолжения не используется. Это предотвращает потерю записей, созданных в одной миллисекунде.

Порядок процессов — время создания и UUID по убыванию; изменение статуса/профиля не перемещает запись. Новые записи перед уже пройденной границей появятся в новом обходе с начала. Изменения ранее просмотренного процесса доставляются через журнал событий/SSE. Это живой обход, а не замороженный снимок всех статусов.

Проверка: `RECRUITMENT_CURSOR_TEST_DATABASE_URL=<disposable-db> pnpm --filter @comit/api exec tsx --test tests/recruitment-cursor.test.ts` проверяет микросекунды, отсутствие пропусков после правки и нового процесса, совпадение ключей между двумя экземплярами и запрет чужого/подменённого cursor.
