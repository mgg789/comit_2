# Итог расширенной выборки и тестового обучения R₀

Этот отчёт фиксирует историческую приёмку до ручного rollout. Следующее явное
решение пользователя включить sort-only R₀ оформлено отдельно в
[активации](rerank-activation.md); численные gates этого отчёта не изменены.

Выборка закрыта: **60 семейств вакансий, 420 профилей**, исправленная разметка
прошла проверку согласованности. Один тестовый цикл обучения и оценки завершён.
**Условия активации не выполнены; runtime-модель не изменена.** Машинный отчёт
с хешами источников, метриками и расходом: [acceptance JSON](../data/validation/rerank-grounded-cohort-acceptance.json).

## Данные и исправления

Сохранено разбиение 32 train / 8 validation / 8 calibration / 12 golden по восьми
направлениям. В каждом семействе семь профилей. Использованы 37 строгих параметров
и реальный Harrier-270m, 640 измерений. Все пять статусов подтверждения присутствуют;
статус профиля не заменяет собственный статус навыка или факта.

Три совпадающих между разбиениями описания получили варианты только в train.
Типизированные факты и статусы сохранены побайтно. Аудит реальным Harrier прошёл:
максимальное косинусное расстояние документа 0,07629, изменение semantic cosine
0,00940, изменение основного score 0,00063. Отсутствие точных совпадений текста
не доказывает независимость синтетических семейств. Консервативный учёт всех
выходов генерации профилей, включая эти варианты: **595 из 600**.

Исходная разметка дала 172/180 согласованных сравнений при перестановке сторон,
но оставила frontend-01 и qa-06 в quarantine. Исходная слепая assistant20 проверка
совпала в 16/20 случаях. Неудачные пилоты v1 и v2 сохранены вместе со всеми
24 и 28 попытками; их ответы и расход не перезаписаны.

V3 отделил 16 class-only семейств с явным локальным правилом от 44 семейств
API-учителя. Правило использует принятый грейд и применимые известные факты
с собственным подтверждением; отсутствие необязательного сигнала не штрафуется.
Это синтетический prior. Все восемь validation-семейств используют это правило;
в calibration и golden локального oracle нет. Получены 384 локальных receipts
без API-вызовов. Nonclass-пилот прошёл 8/8 valid/correct и 4/4 reverse. Из
78 новых API-попыток v3 незавершённым осталось qa-06: повторяющиеся evidence tokens
были отклонены строгим валидатором, без исправления ответа задним числом.

V4 заново разметил целиком только qa-06. Исходная policy сохранена: соответствие
заданному Python, затем собственное подтверждение. Запрос ограничен этими фактами;
два evidence tokens должны быть различны. Новый пилот прошёл 8/8 valid/correct
и 4/4 reverse, семейство — 3/3 reverse. Из 32 логических заданий семь использовали
точный кэш пилота; **25 новых API-попыток**. Остальные 59 семейств не изменены.

Итог: **129/132 reverse comparisons API-учителя и 48/48 локального правила**,
quarantine пуст. На каждом из 12 golden-семейств минимум 16 решающих пар.
Assistant20 с новой явной policy совпал в 20/20 случаях, фактических ошибок и
ручных исправлений labels нет. Перенос неизменных решений на v4 закреплён receipt:
это обновление привязки метаданных, а не ещё 20 слепых решений. Другие 20 пар
для пользователя подготовлены, человеческая проверка остаётся незавершённой.
(Дополнение 08.10.2026: user20 выполнена по policy-corrected пакету repair-v4 —
17/20 согласий, 0 factual issues; [отчёт и статус](rerank-cohort-review.md#выполненная-user20-проверка-repair-v4-08102026).)

Накопленный ledger: **99/120 генерационных, 2423/3000 попарных, 579/600 отдельных
оценок пригодности**. Повторы учтены. Кэш содержит requests, responses, модели,
prompts, фактический token usage там, где он возвращён, и hashes. Token usage в
acceptance JSON относится к указанным namespaces, не ко всей истории генерации;
денежная оценка не заявляется.

## Обучение и результат

Один цикл использовал фиксированную сетку C = 0.01, 0.1, 1, 10, train-only
нормализацию и seed 42. Выбран **C = 0.01**, модель содержит 756 признаков,
intercept отсутствует. Protocol valid сохранён, артефакт test-only,
promotion запрещён. Повторный cache-only запуск с запрещённым fit вернул
тот же отчёт; байты пяти training receipts не изменились.

| Golden, 12 семейств / 238 решающих пар | Основной комбайн | R₀ | Разница |
|---|---:|---:|---:|
| Macro NDCG@10 | 0,995890 | 0,998537 | +0,002647 |
| Macro pair accuracy | 0,918828 | 0,958643 | +0,039815 |
| Micro pair accuracy R₀ | — | 0,957983 | — |

Нижние 95% границы paired bootstrap по семействам: **0,0 для прироста NDCG**
и **−0,005291 для прироста pair accuracy**. Требуемый прирост NDCG 0,02 и обе
положительные нижние границы не достигнуты. Средний прирост pair accuracy
выше 0,03, но этого недостаточно для общего условия активации.

Исходный комбайн имеет NDCG = 1 в восьми из 12 семейств. Максимально возможный
macro-прирост на этой golden-выборке — **0,004110**, меньше требуемых 0,02.
Набор пригоден для проверки механики и начального prior, но не способен
подтвердить заданный выигрыш NDCG даже при идеальном порядке. NDCG улучшился
в трёх семействах, pair accuracy — в пяти и ухудшился в двух.

Описательные срезы pair accuracy по направлениям, без отдельных доверительных
интервалов и с малым числом семейств:

| Направление | Семейств | Средняя разница |
|---|---:|---:|
| Backend | 2 | +0,220238 |
| Frontend | 2 | +0,023810 |
| Fullstack | 1 | −0,055556 |
| Mobile | 1 | 0 |
| DevOps | 1 | +0,047619 |
| Data | 2 | 0 |
| QA | 1 | 0 |
| ML | 2 | −0,001190 |

На calibration прирост NDCG равен нулю, pair accuracy изменился на −0,011607.
Порог хвоста не выбран: calibration содержит только 41 релевантный пример
при требовании минимум 50; golden содержит 67. `tail_gap=null`, отсечение
запрещено. Нули recall в невалидированном gate — служебные значения,
а не измеренный нулевой recall работающего отсечения.

Ограничения: подбор C проверен только на class-only validation; pair policy
и сохранённые независимые suitability grades оценивают разные критерии;
NDCG@10 при семи карточках охватывает все семь. Синтетика не подтверждает
реальные предпочтения работодателей, assistant review не заменяет human review.
Golden уже оценён и не используется для дальнейшей настройки или удобного
исключения семейств. Для проверки выигрыша нужен новый независимый, заранее
зафиксированный benchmark со сложными альтернативами; его генерация не запущена
и бюджет автоматически не увеличивается.
