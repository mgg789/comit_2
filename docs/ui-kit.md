# Общие компоненты интерфейса

Приложения работодателя и кандидата используют общие компоненты из `@comit/ui-kit/design`: `Action`, `Icon`, `PageTitle`, `State`, `Field`, `Reveal`, `Select` и `Backdrop`. Модуль `apps/employer/src/ui.tsx` сохраняет прежние импорты работодателя через реэкспорт.

Подключение: сначала `@comit/ui-kit/tokens.css`, затем `@comit/ui-kit/design.css`; корневой элемент приложения имеет класс `employer-app` или `candidate-app`. Шрифты, фон, стекло, кнопки, навигация, меню аккаунта, поля, раскрытие списков и поведение при уменьшенном движении определены в одном месте. Локальные стили приложений задают только страницы и бизнес-компоненты. Имена существующих токенов `--employer-*` сохранены для совместимости обоих приложений.

Оригинальные SVG, фоновые изображения и шрифты из макета находятся в `packages/ui-kit/src/design-assets/`. `designAsset` возвращает URL, который сборщик разрешает относительно пакета. Приложение кандидата не обращается к пути `/employer/` для общих ресурсов. Специфичные для работодателя ресурсы остаются в его приложении.

## Иконки

`Icon` выводит иконки двух видов, обе окрашиваются через CSS `color` (`currentColor`), поэтому активные пункты навигации, светлые кнопки и меню перекрашивают иконку без фильтров изображения:

- одноцветные глифы, экспортированные из Figma (навигация, поиск, колокольчик, стрелки, инструменты AI и т. п.), — CSS-маска по оригинальному SVG из `design-assets`, геометрия не меняется;
- иконки, которые макет берёт из lucide (резюме, кандидаты, сообщения, карандаш, копирование, сердце, крестик, галочка), — компоненты `lucide-react`.

`arrow` — тёмная стрелка lucide на светлом круге основных действий. Размер задаёт обёртка `.icon` и контекстные CSS-правила; цвета по умолчанию и оттенки, заменившие прежние фильтры (`--employer-nav-icon`, `--employer-search-icon`), — токены `tokens.css`. Новые иконки добавляются только в `Icon`, не прямыми `<img>`.

`Select` сохраняет настоящий элемент `select` и события изменения формы. Панель списка размещается в корневом элементе текущего приложения; размеры, клавиатурное управление и доступность остаются общими. `Reveal` и раскрытие `Select` используют `framer-motion`; настройки уменьшенного движения задаются на уровне приложения. CSS сохраняет ограниченные hover-переходы у управляющих элементов даже при уменьшенном движении, как в приложении работодателя.

## Вход по почте

`@comit/ui-kit/email-login` экспортирует `EmailLogin`. Его стили подключаются отдельно через `@comit/ui-kit/auth.css`. Компонент получает функции `requestCode(email)` и `verifyCode(request)`, обработчик `onLogin(account)`, преобразователь ошибок `errorText(reason)`, необязательные `brandSubtitle` и `consentHref`. Каждое приложение связывает эти функции со своим API и ролью. UI-kit не обращается к API работодателя или кандидата, не хранит сессию и не управляет cookies.

Подтверждение сохраняет обязательное согласие и шесть цифр одноразового кода по действующему контракту сервера. Доступность повторного запроса определяется `resend_after` из серверного ответа. Не подключённый вход через Яндекс показывает явную ошибку и не имитирует авторизацию.

## Проверка

- `pnpm --filter @comit/ui-kit test` — нормализация кода входа (`otpDigits`: автозаполнение и вставка сохраняют все шесть цифр)
- `pnpm --filter @comit/ui-kit typecheck`
- `pnpm --filter @comit/web-employer typecheck`
- `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs node tests/employer-agent-browser.mjs`
- `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs node tests/employer-swipe-browser.mjs`

Браузерные проверки используют синтетические перехваченные ответы API и не выполняют реальные действия с пользователями или провайдерами. Для них требуется локально запущенный Vite приложения работодателя.

## Общая шапка и подтверждения

`@comit/ui-kit/app-shell` предоставляет `AppShellHeader` и `Dialog`. Оба приложения используют одну разметку, CSS и анимацию уже отлаженной шапки работодателя: подписи навигации постоянно смонтированы, меню аккаунта находится рядом с капсулой, а не внутри неё. Роль, ссылки, действия и содержимое меню передаются приложением; ожидание закрытия AI перед поиском и чатами остаётся ответственностью работодателя.

`Dialog` использует прежние классы работодателя `modal-shade`, `modal account-confirmation glass` и `account-confirmation-actions`. Кандидат больше не содержит отдельного оформления модального окна. По умолчанию компонент блокирует прокрутку, удерживает фокус, обрабатывает Escape и возвращает фокус. Работодатель передаёт `manageFocus={false}`, поскольку его существующий общий обработчик управляет также другими окнами. Приложение блокирует закрытие во время отправки через переданный `close`.

Проверка общего компонента: `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs node tests/shared-shell-browser.mjs` сравнивает структуру шапки, постоянные подписи навигации и одинаковые вычисленные стили окна выхода в двух приложениях на синтетических аккаунтах.

## Полные стили и общий чат

`auth.css` содержит все зависимости входа: страницу, кнопку Яндекса, согласие и OTP. Перенос только JSX без этих стилей менял внешний вид кандидата. `Tags` использует те же капсулы и палитру в обоих приложениях.

`RecruitmentConversation` из `@comit/ui-kit/recruitment-conversation` и `conversation.css` переиспользует чат работодателя: сообщения, историю, загрузку и скачивание файлов, отправку и повтор после ошибки. Приложение передаёт транспорт своей роли; доступность отправки определяется серверным `chat_writable`. При повторе сохраняются исходные данные сообщения и ключ идемпотентности.

Проверки при работающих локальных Vite обоих приложений:

- `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs node tests/shared-auth-browser.mjs` — одинаковые стили и геометрия входа/OTP на 1920, 1024 и 390 px, согласие и разделение ролей.
- `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs node tests/conversation-browser.mjs` — история, файлы, повтор отправки, запрет записи и мобильный экран.

Общий `AppShellHeader` принимает `toolsContent` и `overlayContent`: приложения вставляют дополнительные действия и выпадающие панели, сохраняя единые разметку и анимации хедера. Уведомления работодателя используют эти слоты, а состояние и запросы остаются в приложении работодателя. Анимация появления общих модальных окон находится в `design.css` и действует в обоих кабинетах.

Панель `ChatComposer` из `@comit/ui-kit/chat-composer` извлечена из AI-чата и используется без копии разметки и стилей в переписке работодателя и соискателя: авторазмер textarea, Enter/Shift+Enter и IME, плюс, send, multiline, стекло и hover. Приложения сохраняют свои пределы вложений, транспорт, consent/allowed-actions и retry ключи. `RecruitmentChatList` отображает только метаданные плашек. `withChatOrigin` / `chatReturnRoute` сохраняют внутренний путь с фильтрами в `from` и исключают внешние/рекурсивные возвраты. SVG QGramm — точный экспорт Figma 544:1754; подпись ведёт на https://github.com/mgg789/QGramm.

## Сохранение вводов и прочтение чатов

`PersistentStateScope` разделяет несекретные вводы по роли и аккаунту; `usePersistentState` сохраняет управляемые фильтры и черновики в localStorage, синхронизирует вкладки и выдерживает повреждённое или недоступное хранилище. Структурированные поля требуют собственного валидатора. Серверные формы используют ключи с ID и исходной ревизией; подтверждённое сохранение очищает соответствующий черновик. OTP, сессии, содержимое файлов и отметки согласий в этот механизм не входят: согласия всегда читаются с сервера.

Общий `VacancyCardArrow` и hover иконок капсулы перенесены из работодателя без второго оформления. `RecruitmentChatList` заменяет статус процесса числом новых входящих сообщений только при положительном серверном `chat_unread_count`. `RecruitmentConversation` подтверждает последовательность последнего реального входящего сообщения, когда конец истории виден в активной вкладке; ошибки подтверждения повторяются и не блокируют переписку. Из списка история не читается. Проверки: `pnpm --filter @comit/ui-kit test`, `tests/candidate-polish-browser.mjs`, `tests/employer-showcase-browser.mjs`, `tests/conversation-browser.mjs`.

## Публичная витрина

`PublicShellHeader` использует ту же внутреннюю навигацию, логотип и анимации, что `AppShellHeader`, а справа принимает ссылку входа. Ресурс `public-login.svg` сохраняет геометрию оригинального экспорта Figma. Общие стили `vacancy-grid` / `vacancy-card` перенесены из работодателя в `design.css`: работодатель и публичная витрина используют единые карточки и адаптивную сетку. Публичные карточки могут увеличиваться по высоте для длинного названия.

`Backdrop` принимает `imagery={false}`, чтобы публичная витрина использовала собственные исходные фоновые ленты welcome, сохраняя общий затемняющий слой. По умолчанию `imagery=true`, внешний вид обоих кабинетов сохраняется.

## Переход по логотипу

Логотип в шапках обоих кабинетов, публичной витрины и на общем экране входа ведёт на общую главную с выбором витрины, работодателя и соискателя. `homePageHref(origin, development, override)` из `app-shell` возвращает `/` в production и тот же хост/протокол с портом welcome 5176 в Vite. `VITE_WELCOME_URL` позволяет задать иной базовый адрес главной. `EmailLogin` принимает `homeHref`; его логотип и «Назад» используют эту ссылку без действий с сессией.

## Общий поиск списков

`InlineSearch` из `@comit/ui-kit/design` использует исходный `discovery-search` работодателя. Он получает `value`, `onChange`, доступное название `label`, необязательные `placeholder`, `inputRef`, `onSubmit` и `className`. Submit предотвращает перезагрузку: поиск соискателей подтверждает запрос кнопкой или Enter, собственные вакансии и предложения кандидата фильтруются при вводе. Исходные CSS-правила фокуса и мобильных размеров перенесены в `design.css`, без второго набора стилей в приложениях. Поле сохраняет локальное состояние силами вызывающего списка.

## Уведомления и обратная связь

`SystemInbox` (`@comit/ui-kit/system-inbox`) переиспользует layout и пузырьки переписки, но намеренно не предоставляет send/attachment/composer. Caller передаёт role-bound transport и navigate; внутренние ссылки проходят allowlist. Receipts относятся только к доставленным видимым сообщениям. `useChatUnread` читает подтверждённые счётчики аккаунта, сбрасывает их при смене account ID и повторяет чтение после событий `comit:chat-read`.

`RecruitmentChatList` принимает optional `system` для логотипа, `AppShellHeader` — nullable `secondaryUnreadCount` для badge 99+. `RecruitmentClock` из design отображает RecruitmentDeadline, используя shared weekday helper; business transitions принадлежат серверу. `RejectionFeedback` и чистый `rejectionFeedbackError` задают единые требования подробной ОС во всех формах работодателя.

## Область истории и загрузка

`chat-page` ограничивает кабинет высотой окна, `chat-history-viewport` задаёт мягкие края истории с маской и блюром, не перехватывая клики. `RecruitmentConversation` прокручивает собственный список вместо `scrollIntoView`; `SystemInbox` подтверждает чтение через observer с корнем в списке сообщений. Спиннер сохраняет непрерывное вращение при reduced motion: это обратная связь о незавершённой загрузке; декоративные анимации сохраняют общий режим уменьшения движения.

Регрессия `tests/chat-viewport-browser.mjs` проверяет оба кабинета на desktop/mobile с синтетическими API: документ не прокручивается, последнее действие доступно выше мягкого края и мобильной навигации. Дополнительно реальные локальные чаты проверены в 12 сочетаниях роли, типа чата и размера окна.

## Ширина списков и поиск

Общий `Select` измеряет подписи вариантов и может открыть список шире поля. Ширина ограничена 560 единицами дизайн-системы и доступной шириной окна с отступом 8 px; позиция учитывает фактическую ширину списка. Активация встроенного поиска использует общий `discovery-search:focus-within` для обеих ролей.
