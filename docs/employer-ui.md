# Интерфейс работодателя

Реализация находится в `apps/employer`, исходный дизайн — [Figma](https://www.figma.com/design/gPFLCJKXEoRwRP3YLyMsX4/Untitled?node-id=1-49). Все данные загружаются через существующий `@comit/api-client`; демонстрационные профили и ответы в приложении отсутствуют.

## Страницы и сценарии

Локальный адрес Vite: `http://127.0.0.1:5174/employer/`. Без действующей сессии отображается вход. Для проверки остальных страниц нужен запущенный API с настроенной авторизацией; адрес страницы не обходит проверку сессии.

| Адрес после `/employer/#` | Сценарий |
|---|---|
| `/vacancies` | Все, открытые и закрытые вакансии; редактор новой вакансии |
| `/vacancy/:draft_id` | Требования, подбор со свайпом, избранное, приглашения, интервью |
| `/vacancy/:draft_id/resumes` | Резюме и реальные состояния процессов по вакансии |
| `/resumes` | Резюме по всем собственным вакансиям; фильтр нескольких вакансий справа от заголовка |
| `/showcase` | Общая витрина кандидатов: поиск, фильтры и добавление в вакансию |
| `/resume/:candidate_id?draft=:draft_id` | Анонимный профиль, доказательства, PDF и приглашение |
| `/chat` | Список доступных переписок |
| `/chat/:process_id` | Переписка, файлы, контакты после принятия, интервью и оффер |
| `/statistics` | Данные за период UTC, этапы найма и ежедневная активность |

Замените `:draft_id`, `:candidate_id`, `:process_id` реальными ID из API. Переходы из списка вакансий, карточек кандидатов и списка чатов формируют адреса автоматически. Новая вакансия открывается кнопкой добавления на странице вакансий; AI-чат — кнопкой агента поверх текущей страницы.

Вход использует email OTP и HttpOnly cookie, JWT не сохраняется в browser storage. Согласие на обработку данных даётся явно. Постоянный AI-чат открывается поверх любой страницы и сохраняет состояние при смене адреса; история, задания, вопросы, документы и бюджет принадлежат текущему аккаунту. Отдельный heartbeat присутствия работает на всём интерфейсе, а не только в открытом AI-чате.

Первая колонка списка вакансий — черновики. Вторая вкладка меню — резюме, AI открывается отдельной круглой кнопкой. Корневые страницы не показывают «Назад», кроме чатов с возвратом к вакансиям; вложенные карточки сохраняют возврат. Общая страница резюме объединяет сохранённые публичные карточки и процессы по вакансиям владельца; для каждой вакансии сохраняются отдельные cursors. Статусы одной кандидатуры в разных вакансиях не смешиваются. Нативные dropdown заменены клавиатурными listbox, сохраняющими реальные form values и существующие API handlers.

Поиск в капсуле аккаунта открывает кандидатов и сразу фокусирует поле; повторное нажатие возвращает фокус в поиск. Селектор резюме сохраняет множественный выбор в белом меню, стрелка в круге поворачивается при открытии. Статистика использует общую сетку строк с ежедневным графиком, donut текущих статусов и сравнительными полосами независимых этапов. Нулевые данные не подменяются демонстрационными значениями.

Прикреплённые PDF/TXT/MD показаны отдельными карточками над вводом; загрузка не меняет набранный текст. Удаление карточки отменяет привязку к следующему сообщению, не удаляя документ из хранилища. Существующий message API получает реальное имя и ID документа в тексте запроса, отдельного поля attachments у него нет. Ввод и подпись Droidje AI совместно выезжают снизу; бюджетная капсула использует ту же анимацию появления и исчезновения, что reasoning.

Ввод AI растёт до восьми строк и затем прокручивается: Enter отправляет, Shift+Enter добавляет строку, подтверждение IME не отправляет сообщение. Ползунок reasoning плавно перемещается между тремя режимами. Стеклянный фон интерактивных кнопок вынесен в отдельный слой, foreground не фильтруется.

В AI-панели отображается оставшийся бюджет с учётом резервов. Reasoning открывается при hover/focus как горизонтальная капсула `low / max` с тремя положениями: без размышлений, средний и максимальный. Выбор передаётся в `reasoning_effort` следующего сообщения и участвует в idempotency; backend сохраняет его на turn. Для DeepSeek средний режим соответствует `high`, максимальный — `max`; прежние запросы без поля остаются без reasoning. Требуется миграция `008_organization_reasoning.sql` агента. Реальный провайдер и бюджеты по-прежнему требуют отдельной настройки.

Попытка входа без согласия выделяет чекбокс, переводит на него фокус и показывает пояснение. Нажатие на подпись открывает публичную политику в отдельной вкладке, не меняя согласие. Маршрут `/legal/privacy-policy` доступен без сессии; текст берётся из `docs/legal/privacy-policy.md`, остальные ссылки документов также открывают канонические файлы `docs/legal/`.

Создание вакансии: ручной ввод → сохранение → проверка → явное подтверждение summary → публикация → ожидание готовности подбора. Редактирование защищено ревизией. У создания черновика нет backend idempotency key: при неоднозначном сетевом результате повторное создание блокируется, предлагается проверить список вакансий. Лайк, свайп, приглашение и сообщение используют UUID; повтор неизменённого запроса сохраняет ключ. Карточка продвигается после подтверждения сервера. Impression учитывается при фактической видимости.

Общая витрина показывает анонимные профили. Несоответствие строгим фильтрам требует отдельного подтверждения полученного `mismatch_token`. Контакты доступны только через защищённый endpoint процесса. Файлы QGramm до 8 MiB, документы агента PDF/TXT/MD до 5 MiB. PDF резюме открывается только по защищённому same-origin пути `/api/`.

## Визуальная система

Оригинальные экспортированные ассеты находятся в `apps/employer/public/design`. Inter, Murs Gothic Wide Dark и Moon Walk поставляются локально. Employer-токены в `packages/ui-kit/src/tokens.css` ограничены `.employer-app`; остальные приложения сохраняют прежнюю палитру. Desktop-геометрия масштабируется относительно макета шириной 1920 px; до 760 px используется самостоятельный мобильный layout. Motion учитывает `prefers-reduced-motion`.

Стеклянные поверхности используют SVG displacement с двухканальной картой преломления у краёв, backdrop blur, насыщенность и световые границы. Поддержка SVG backdrop filters зависит от браузера; при отсутствии поддержки остаются blur и световые границы. CSS `@supports` подтверждает синтаксис, но не одинаковый результат рендеринга во всех браузерах.

## Неподдержанные контракты макета

- OAuth Яндекса: endpoint отсутствует; кнопка проверяет согласие и явно объясняет необходимость входа по email.
- Фото работодателя/кандидата: поля отсутствуют в `AccountView` и публичных профилях. Используются анонимные аватары; люди из макета не выдаются за реальные записи.
- Отдельный обязательный грейд вакансии: отсутствует в `AgentsDraftFields_Input`. Передаются специализация и уровни навыков действующего реестра.
- Карточки используют `created_at` для черновиков, `published_at` для открытых и `closed_at` для закрытых. Даты жизненного цикла требуют миграции `009_vacancy_dates.sql`; неизвестные исторические даты отображаются как «Дата … не указана».
- Политики маршрутизации из dropdown `3:9124` и очистка истории AI не имеют employer API. Из макета перенесён стиль меню, вымышленных действий нет.
- Рыночные зарплаты отсутствуют в `EmployerStatistics`: статистика показывает реальные собственные counts, inventory и daily. Этапы не интерпретируются как вложенная когортная конверсия.
- Профиль компании не имеет отдельного endpoint: название и текст приглашения вводит работодатель.

## Запуск и проверка

```sh
pnpm install --frozen-lockfile
COMIT_API_URL=http://127.0.0.1:8080 pnpm --filter @comit/web-employer dev --host 127.0.0.1
pnpm --filter @comit/web-employer build
pnpm typecheck
node tests/employer-browser.mjs
```

Dev proxy удаляет `/api` перед обращением к API-core. Для входа и рабочих данных backend должен быть настроен согласно [auth.md](auth.md), [agents.md](agents.md), [chat.md](chat.md) и [vacancy-crud.md](vacancy-crud.md).

Browser-тест использует Playwright и установленный Chrome. Если пакет не установлен локально, задайте `PLAYWRIGHT_MODULE` абсолютным путём к `playwright/index.mjs`. `EMPLOYER_SCREENSHOTS` задаёт каталог снимков, `EMPLOYER_BROWSER_URL` — адрес Vite. Синтетические ответы перехватываются только внутри теста: они проверяют UI-контракты, а не доступность живого SMTP, моделей или QGramm. Общий smoke выполняется отдельно через `./tests/smoke.sh` с портами запущенного стека.

Для локальной разработки можно использовать отдельный Mailpit SMTP с STARTTLS и локальным сертификатом. API и mail worker доверяют этому сертификату через `NODE_EXTRA_CA_CERTS` только своих процессов; глобальное хранилище сертификатов не меняется. В таком контуре код действительно генерируется API, доставляется SMTP worker и проверяется по PostgreSQL; письмо читается в Mailpit, внешняя почта не используется. Новая изолированная база содержит пустой рабочий кабинет, пока пользователь не создаст записи.

При перезапуске локального API необходимо восстановить его параметры БД, авторизации, сервисов и SMTP: успешный `/healthz` не подтверждает настройку входа. `503 auth_not_configured` означает потерянную конфигурацию; ожидаемый ответ `/auth/employer/me` без сессии — `401`. Ссылка в подписи чекбокса открывает текст согласия; отдельная дублирующая подпись не выводится.

AI допускает максимум три выбранных вложения. Приветствие размещается независимо от высоты файлов, ошибок и ввода; оригинальный логотип стоит перед всей серой строкой атрибуции. Все маршруты работодателя используют favicon из Figma `1:2398`. Запросы API без тела не объявляют JSON Content-Type, иначе пустой POST выхода отклоняется парсером. Загрузка документов доступна независимо от AI: `agent_disabled_manual_available` означает неподключённый провайдер, а не ошибку файла; выбранные документы сохраняются при неуспешной отправке.

См. также: [architecture.md](architecture.md), [employer-statistics.md](employer-statistics.md), [candidate-showcase.md](candidate-showcase.md), [recruitment.md](recruitment.md).

Панель подтверждения почты повторяет Figma `1:2498`: стеклянные ячейки, динамический email, кнопка «Продолжить» и подсказка о папках почты. Макет содержит пять ячеек, но действующий OTP-контракт требует шесть цифр; интерфейс сохраняет шесть ячеек в той же ширине. Единое нативное поле поддерживает вставку и `one-time-code`, визуальные ячейки отражают его значение; подтверждение доступно только при полном коде. Галочка согласия чёрная.

При удалении цифры OTP позиция активной ячейки и значение обновляются вместе; рамка фокуса переключается без задержки. Индикатор начальной загрузки AI появляется только после 450 мс ожидания. Ошибки вложений отделены от ошибок отправки и объясняют известные ограничения документа, не выводя произвольные ответы сервиса; повторный выбор того же файла доступен и после клиентской ошибки.

Вкладка `#/settings` показывает реальные данные аккаунта и бюджета. Настройки этого браузера управляют глубиной рассуждений при открытии AI, отправкой по Enter и уменьшением анимации; приватные данные и токены в localStorage не сохраняются. Выход из текущей или всех сессий выполняется только после подтверждения, ошибки остаются в модалке. Меню аватара закрывается при клике вне него. Удаление аккаунта не подключено: отсутствуют authenticated DELETE-контракт и координированное удаление данных accounts/recruitment, agents-service и matching-engine. Кнопка открывает объяснение ограничения, не имитирует удаление и не отзывает сессии вместо него.

Создание вакансии: кнопки, поля и селекторы одной высоты; секция стека раскрывается с анимацией и разделителями. Начальный прогресс — 0%; он учитывает шесть заполненных текстовых/зарплатных полей, не заранее выбранную специализацию. Удаление требования означает отсутствие ключа в карте, а не уровень 0. Семь видимых грейдов `intern`, `junior`, `junior+`, `middle`, `middle+`, `senior`, `senior+` соответствуют существующим API-значениям 1–7; новый навык получает `middle` (4). Кнопки используют изолированную стеклянную поверхность; окно закрывается кликом по фону или Escape, пока запрос не выполняется.

После проверки открываются вкладки «Инфо», «Стек», «Хард», «Софт». Инфо содержит подписи полей, без стека. Остальные вкладки редактируют настоящие карты `stacks`, `domens`, `soft_skills`: точки двигаются вдоль лучей, поддерживается клавиатура; неподключённые навыки не рисуются. Стек группируется визуально по дизайну/фронтенду, средам выполнения, хранилищам и инфраструктуре; домены — по инженерным и аналитическим темам, софт — по коммуникации/руководству и организации работы. Это порядок отображения, индексы и веса matching не меняются. Невидимые панели участвуют в общей grid-высоте, но исключены из взаимодействия и доступности; при переключении размер окна сохраняется.

«Назад» возвращает к форме, «Черновик» сохраняет изменённые требования без публикации, полная нижняя кнопка подтверждает публикацию. Если после проверки изменили диаграмму, перед публикацией выполняются CAS-patch и новое approval; отправляется hash именно этой версии. При ошибке изменения остаются в форме. Действующие контракты уже поддерживают все три группы, новые endpoint или миграции не нужны. Неоднозначное создание по-прежнему блокирует повтор, чтобы не создавать дубликат.


Компактная проверка вакансии: добавление навыка в начальной форме обозначено плюсом. На вкладках «Стек», «Хард», «Софт» остаются только точки грейда и удаление крестиком рядом с названием оси; отдельные ползунки и плашки отсутствуют. Круглый плюс внутри правого нижнего угла диаграммы открывает существующий селектор справа (при нехватке места — слева). Кнопки возврата, черновика и публикации находятся только в «Инфо»; все панели занимают общую сетку, поэтому высота определяется максимальным содержимым.

На странице вакансии требования подписаны грейдами. Публикация/отзыв доступны рядом с редактированием, окончательное закрытие и удаление — внизу. Каждое действие требует подтверждения; закрытая вакансия не редактируется и не публикуется повторно. Удаление предлагается только для черновика или закрытой вакансии. Серверные последствия и координация сервисов описаны в [vacancy-crud.md](vacancy-crud.md).


Переписка сохраняет доступность чтения через `chat_available`, а отправка и вложения управляются отдельным `chat_writable`. При неактивной вакансии composer отключён с пояснением, история остаётся видимой.

Проверка этого изменения: `pnpm --filter @comit/web-employer typecheck`, `pnpm --filter @comit/api typecheck`, `pnpm --filter @comit/shared typecheck`, `pnpm --filter @comit/api-client typecheck`, `git diff --check` прошли. На изолированном локальном стенде применены agents 010, matching 016, API 011/012; health API/agents/matching/chat и регистрация lifecycle routes подтверждены HTTP. Настоящий локальный QGramm ответил 200 на отправку синтетического сообщения и очистку его процесса. Полный vacancy/recruitment сценарий, browser-проверка и тестовые наборы в этом цикле не запускались по запросу пользователя.


## Колонки вакансий и автоматическая лента

Все собственные вакансии одновременно распределяются по трём колонкам: «Черновики», «Открытые», «Закрытые». Заголовки не являются переключателями; поиск применяется ко всем колонкам. Карточка растёт по содержимому, показывает до трёх технологий и зарплату в полных рублях с суффиксом «р». Публикация/отзыв располагаются справа в заголовке страницы вакансии.

Вкладки требований используют увеличенную диаграмму; подписи закреплены у своих радиусов, удаление доступно простым крестиком из макета. В капсуле хедера иконка сообщений открывает переписку.

Опубликованная вакансия автоматически запускает подбор. Пустая лента показывает «Не можем найти подходящих кандидатов» и «Обновить»; ожидающее пополнение — «Обновляем ленту» без кнопки. Интерфейс опрашивает хвост той же сессии; устаревшая/истёкшая сессия пересоздаётся. Если обработка не продвинулась за 90 секунд, появляется возможность обновить вручную. Подробности N1 и refill-worker — в [matching.md](matching.md#автоматическое-пополнение-ленты).

Проверки текущей итерации: typecheck employer/API/shared/api-client, сборка API с упаковкой CID-assets, Python compileall и git diff --check прошли. Локальные health API/agents/matching вернули HTTP 200; OpenAPI содержит routes восстановления и пополнения ленты. Наборы тестов и browser-проверка не запускались по запросу пользователя; реальная внешняя почта не отправлялась.
