# Общая входная страница и публичная витрина COMIT

`apps/welcome` реализует главную страницу Figma `544:7221` и публичные вкладки вакансий `544:7364` / соискателей `544:7635`. Используются исходные фоновые изображения, SVG и шрифты, уже подключённые на главной. Шапка, навигация с анимацией, поля, модальное окно, теги, карточки вакансий взяты из общего `@comit/ui-kit`; второй набор аналогичных компонентов не создаётся.

Главная доступна по `/`; кнопка витрины открывает `#/showcase/vacancies`, переключение соискателей — `#/showcase/candidates`. Логотип в шапке витрины и обоих кабинетов ведёт на общую главную `/`; в локальном Vite — на 5176 того же хоста (или `VITE_WELCOME_URL`). «Войти» в шапке витрины возвращает на `#/`. Иконка входа — оригинальный экспорт Figma `93782.svg`, включённый в общие ресурсы как `public-login.svg`.

Кнопки ролей ведут в существующие приложения `/candidate/` и `/employer/`. Их собственный запуск проверяет роль сессии и показывает кабинет либо общий компонент входа; welcome не хранит и не копирует сессии. В режиме Vite адреса используют текущие хост и протокол, порты кандидата 5173 и работодателя 5174. `VITE_CANDIDATE_URL` и `VITE_EMPLOYER_URL` позволяют указать другие полные базовые URL. Главная запускается на 5176. Для локального кандидата на 5177 используется `VITE_CANDIDATE_URL=http://127.0.0.1:5177/candidate/`.

Витрина получает реальные страницы `GET /api/public/showcase/vacancies` и `GET /api/public/showcase/candidates`. Vite проксирует `/api` на локальный API 8080. Правила публикации, анонимизации и DTO описаны в [public-showcase.md](public-showcase.md). Публичные кандидаты представлены направлением, оценённой категорией, городом, навыками и зарплатной вилкой; имена, контакты, PDF и внутренние ID не выдаются. Вакансии показываются только при актуальной опубликованной версии и открытом состоянии. Ошибки, пустые ответы и загрузка отображаются явно.

Отдельные кнопки со стрелками на карточках публичной витрины не показываются. Карточка открывает только окно «Для этого действия требуется войти». На вкладке вакансий первой идёт кнопка кандидата, на вкладке соискателей — работодателя. Закрытые API деталей, резюме и откликов не вызываются. Окно поддерживает Escape, удержание и восстановление фокуса; ссылки ролей используют те же адреса, что главная.

Фильтры направления, грейда и стека и текстовый поиск передаются серверу. Сортировка — по дате публикации, поскольку публичный контракт не содержит частоты использования. Фильтры сохраняются отдельно для двух вкладок через `PersistentStateScope`. Пагинация использует серверный курсор; смена фильтров исключает применение устаревших запросов. На 1920 px вакансии расположены в три колонки, на 1024 — в две, на 390 — в одну.

Проверки:

- `pnpm --filter @comit/web-welcome typecheck`
- `pnpm --filter @comit/web-welcome build`
- `PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs node tests/welcome-showcase-browser.mjs`

Браузерный тест использует синтетические ответы API без действий с настоящими аккаунтами: проверяет маршруты, порядок ролей, запрет деталей, пагинацию, фильтры после перезагрузки, ошибки и геометрию на 1920, 1024 и 390 px. Проверка настоящих публичных GET выполняется отдельно на запущенных API и matching-engine.
