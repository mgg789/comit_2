# Integration engine — внешние данные и верификация

> Статус: каркас с мок-реестром ФСП. Решение о выделении сервиса — 2026-10-05 (context/80).

## Назначение

Единая точка работы с внешними источниками данных профиля:

- **исходящие коннекторы** — получение и верификация данных из внешних реестров;
- **входящие моки** — демонстрационные реестры там, где реального API на хакатоне нет (ФСП).

## ФСП (главный внешний источник по ТЗ)

Реальный API ФСП не предоставляется намеренно (ТЗ §2): мы сами моделируем, какие сведения о
достижениях имеет смысл получать и показывать работодателю. Наиболее удачные решения ФСП учтёт
при проектировании реальной интеграции — поэтому контракт держим аккуратным и документированным.

Предлагаемая структура профиля участника (мок: `src/integration_engine/fsp_mock.py`):

```json
{
  "fsp_id": "fsp-001",
  "display_name": "Иван Иванов",
  "rank": "I",                       // III → I, КМС, MS
  "rating": 1876,                    // ELO-подобный рейтинг
  "events": [{"title": "...", "year": 2025, "place": 7}],
  "certificates": ["Школа ФСП: алгоритмы, 2024"]
}
```

Отображение работодателю: бейджи + блок «Спортивный профиль» в карточке; влияние на подбор —
`fspBoost` в скоринге и приоритет в ранжировании внутри категории.

## Обязательная семантика отсутствия истории

`GET /fsp/participants/{id}` → **404** — это нормальный, must-handle случай (ТЗ: «обязательна
только корректная обработка случая, когда истории ФСП у кандидата нет»). Платформа рендерит
профиль без блока ФСП, не ломая выдачу. Регресс-тест: `test_missing_fsp_history_is_404_not_500`.
