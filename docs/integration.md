# Integration engine — внешние данные и верификация

> Статус: контур ФСП по ТЗ реализован и встроен в продукт; дополнительный
> скоринговый буст полностью подготовлен модельно и интеграционно и ждёт
> реальных данных. Решение о выделении сервиса — 2026-10-05 (context/80).

## Назначение

Единая точка работы с внешними источниками данных профиля:

- **исходящие коннекторы** — получение и верификация данных из внешних реестров;
- **входящие моки** — демонстрационные реестры там, где реального API на хакатоне нет (ФСП).

## ФСП: контур реализован (2026-10-08)

Реальный API ФСП не предоставляется намеренно (ТЗ §2) — команда сама проектирует,
какие сведения о достижениях продукт получает и как их использует. Контур полностью
работает на мок-реестре и покрыт тестами:

1. **Профиль.** Кандидат указывает свой ID ФСП в профиле (`fsp_id`). Платформа
   сама проверяет его в реестре (`integration-engine`), сервер записывает
   верифицированный блок — ранг, рейтинг, турниры, сертификаты — как **evidence**
   (подтверждение) с провенансом `fsp-registry`. Клиент не может подделать этот
   канал: подтверждение ставит только сервер. Отсутствие истории ФСП — штатный
   случай (ТЗ §2): реестр отвечает 404, профиль сохраняется со статусом `pending`,
   ничто не блокируется.
2. **Подтверждение навыков.** Верифицированные достижения ФСП — объективное
   подтверждение практических навыков (ТЗ §1): если кандидат заявил домен
   `algorithms`, сервер поднимает его статус в `confirmed` с провенансом
   «ранг/рейтинг ФСП». Подтверждение влияет на скоринг через стандартные
   коэффициенты доверия и попадает в объяснение карточки.
3. **PDF-резюме.** Блок «Спортивный профиль» печатается в публичном и приватном
   PDF: ID ФСП, ранг, рейтинг, турниры с местами, сертификаты. Личное имя из
   реестра в снапшот не попадает — публичный артефакт остаётся обезличенным.

Предлагаемая структура профиля участника (мок: `src/integration_engine/fsp_mock.py`):

```json
{
  "fsp_id": "fsp-001",
  "display_name": "Иван Иванов",
  "rank": "I",
  "rating": 1876,
  "events": [{"title": "...", "year": 2025, "place": 7}],
  "certificates": ["Школа ФСП: алгоритмы, 2024"]
}
```

`display_name` остаётся только в реестре: в продуктовый снапшот и PDF идут
ранг, рейтинг, турниры и сертификаты.

## ФСП-буст: полностью готов, включается реальными данными

Дополнительное усиление для олимпиадников — **скоринговый буст** за
верифицированные достижения — спроектирован и реализован как завершённый
компонент (`fsp_boost.py`, `fsp-boost-draft-v1`): формула с ограниченным
бонусом (нормированный рейтинг + вес ранга, кап 0.06), структурные факторы
объяснения, строгий ноль для обязательного случая «истории нет», unit-тесты.
Интеграционная точка в комбайне определена и задокументирована.

**Мы осознанно не подключаем буст к живому ядру до появления реальных данных.**
Без настоящего API ФСП и релевантной истории участников любой буст, откалиброванный
на двух синтетических записях реестра, — это мусор, который может ухудшить
выдачу, выглядя при этом уверенно. Подключение — управляемая операция: включение
меняет `ScoringPolicy`, после чего реранкер R₀ штатно переобучается под новую
политику (защита от тихого дрейфа весов), а готовая ablation-инфраструктура
измеряет вклад буста тем же протоколом, что и вклад вектора и рейтинга. База
готова целиком: ждём реальные данные — включаем, измеряем, улучшаем.

## Обязательная семантика отсутствия истории

`GET /fsp/participants/{id}` → **404** — это нормальный, must-handle случай (ТЗ: «обязательна
только корректная обработка случая, когда истории ФСП у кандидата нет»). Платформа
рендерит профиль без блока ФСП, не ломая выдачу. Регресс-тест: `test_missing_fsp_history_is_404_not_500`.
