# Проверка учителя с точными ссылками на факты

После [восстановления транспорта](rerank-transport-recovery.md) добавлен отдельный
контракт `rerank-pair-grounded-v5` для Qwen/Gemma. По умолчанию эксперимент
по-прежнему использует прежнего SystemOne. Новый контракт применяется только
явно, не переписывает существующие ответы, промпты и наборы обучения.

Ответ содержит метку, точные ссылки на факты обеих сторон, отдельные ссылки на
явно неизвестные значения, арифметическое направление зарплаты и фиксированный
код причины. Свободного текста и придуманной уверенности нет. Локальная проверка
отклоняет дополнительные или повторяющиеся JSON-поля, чужие и изменённые ссылки,
подмену статуса, неверную зарплатную арифметику и противоречие метки коду причины.
Объяснение строится кодом из исходных значений. Статус синтетической записи
сохраняется как статус источника; он не доказывает подтверждение каждого её поля.
Этот контракт гарантирует точность цитирования, но сам по себе не гарантирует
соблюдение предпочтений работодателя.

Каждый пилот фиксирует десять пар и обе ориентации до HTTP: максимум 20 попыток,
до пяти параллельных запросов, без автоматических повторов. Требования к
симметрии и согласованности используют все ожидаемые пары; отдельно публикуются
метрики только по валидным ответам. Завершённый отчёт воспроизводится из кэша
без HTTP, чтения ключа и изменения ledger. Прерванный запуск требует разбора
сохранённых receipts. HTTP 401/403/404 останавливают следующий batch; для 400/422
необходимо минимум две классифицированные ошибки схемы в завершённом batch.
Одиночный неправильный ответ не прекращает остальные запросы.

Проверены два отдельных пилота с одной версией промпта:

| Проверка | Валидные ответы | Симметрия | Согласие в обеих ориентациях | Решающие пары |
|---|---:|---:|---:|---:|
| Исходные предпочтения | 20/20 | 10/10 | 6/10 | 6/6 |
| Новые явные критерии | 20/20 | 9/10 | 9/10 | 6/6 |

В исходных четырёх неоднозначных парах не заданы минимальный технический уровень
и порядок обмена технической силы на экономию и командность. Расхождение с
прежней оценкой ассистента не превращено в доказанную ошибку учителя: старые
метки сохранены. Для второго пилота созданы новые варианты требований и
предпочтений, новые ID и отдельная проверка ассистентом вслепую **до** вызовов
модели. Факты кандидатов, семейства и исходные split сохранены; варианты не
становятся независимой от исходников golden-выборкой.

Второй пилот проходит заранее фиксированный порог устойчивости, но сохраняет
одну ошибку политики: `72a0e0b06a8d8bc8`, backend-06, кандидаты 1/2. Единственный
критерий — измеренный uptime, которого нет у обоих. Qwen вернул B/tie вместо
insufficient/insufficient. Цитаты и статусы точны, однако посторонние признаки
не могут заменить этот критерий. Пара исключена из будущих учебных меток;
ответы не исправлены и не скрыты. Независимая человеческая оценка не проводилась.

[Факты, ответы, hashes, расход и результаты проверки](../data/validation/rerank-grounded-teacher-pilot.json).
Actual usage первого пилота: 23 156 input + 3 359 output = 26 515 tokens;
второго: 23 582 + 3 235 = 26 817 tokens. Это измеренные токены, стоимость не
оценивалась. Ledger после обоих: generation 28/120, pair 736/3000, grade 119/600.
Старый лимит 20 попыток закрыт на pair=696; новые два ограниченных пилота
используют прежний общий лимит 3000, не увеличивая его. Старые cache bytes
сохранены, новые запросы имеют собственные identities.

```sh
PYTHONPATH=services/matching-engine/src services/matching-engine/.venv/bin/python -m matching_engine.rerank_grounded_pilot
PYTHONPATH=services/matching-engine/src services/matching-engine/.venv/bin/python -m matching_engine.rerank_grounded_pilot --explicit-policy
```

Полный набор из 60 семейств требует отдельного пространства данных и явной
идентичности нового учителя: прежний набор нельзя незаметно доразметить другим
контрактом. Отдельные оценки пригодности, обучение, golden-метрики и непересекающиеся
20+20 ручных проверок остаются следующими этапами. Эти диагностические пары
не являются обучающим набором; teacher promotion и активация R₀ не выполнялись.
Публичные контракты и backend runtime не изменены.

Проверено: `PYTHONPATH=services/matching-engine/src services/matching-engine/.venv/bin/python -m pytest services/matching-engine/tests -q`
с настроенной отдельной PostgreSQL test DB — 610 passed; scoped Ruff из каталога
matching-engine, `pnpm typecheck`, `pnpm build`, `make smoke` — зелёные.
`pnpm --filter @comit/api test`: 27 passed, 4 skipped из-за отдельных ненастроенных
auth/profile test DB. Production, удалённый CI и полная learned R₀ приёмка
не проверялись.

После интеграции параллельного employer feed из `dev` (`c0d6b7c`) повторены
проверки объединённого дерева: 636 Python/PostgreSQL tests passed, scoped Ruff,
`pnpm typecheck`, `pnpm build`, API 27 passed / 4 skipped, smoke 12 checks passed.
Конфликты двух дополненных документов разрешены сохранением обоих разделов;
исходный учитель, frozen diagnostic receipts и код ленты сохранены.
